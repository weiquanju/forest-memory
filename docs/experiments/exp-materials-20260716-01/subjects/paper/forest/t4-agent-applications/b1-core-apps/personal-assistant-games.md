# 个人助理与开放世界游戏中的记忆

## 个人助理（Personal Assistant）

### 核心需求

| 需求 | 记忆作用 |
|------|---------|
| 长期对话一致性 | 记住历史对话以维持上下文 |
| 个性化响应 | 记住用户风格和事件以提供定制化回复 |

### 代表性实现

| 模型 | 记忆策略 | 核心机制 |
|------|---------|---------|
| MemoChat [94] | 对话内容存储 + 主题索引检索 | 按主题分段摘要 → Key 索引 |
| MPC [101] | 重要信息提取 + 存储 + 未来推理检索 | Chain-of-Thought 忽略无关记忆 |
| AutoGen [153] | 保留重要上下文作为记忆 | 多 Agent 对话框架 |
| Pan et al. [164] | 用户上下文存储 + 工具使用扩展知识 | 信息寻找任务 |

### 设计模式

- **主导形态**：文本检索式记忆（Retrieval-based textual memory）是主流
- **存储内容**：事实性信息 + 用户个人风格
- **检索原则**：识别并检索与**当前查询和上下文**相关的记忆，确保Agent正确理解用户需求

## 开放世界游戏（Open-world Game）

### 核心需求

| 需求 | 记忆作用 |
|------|---------|
| 避免重复错误 | 存储过往成功/失败的 trial |
| 高效探索 | 基于经验选择探索方向 |
| 知识获取 | 外部数据库/API 获取通用知识 |

### 代表性实现

| 模型 | 记忆类型 | 策略 |
|------|---------|------|
| Voyager [99] | 技能记忆（可执行代码） | 保存已获取技能供未来复用 |
| GITM [93] | 成功轨迹 + 外部 Minecraft Wiki | 相似任务检索 + API 获取 |
| JARVIS-1 [159] | 多模态记忆知识库 | 检索交互经验提供 prompt 示例 |
| LARP [161] | Working Memory + 过往经验 + 外部数据集 | 多层记忆体系 |

### 设计模式

- **经验驱动**：无论试内还是跨试信息，核心是反思过去交互并提炼可应用于后续探索的经验
- **内外结合**：除了通过自身 trial 积累经验，吸收外部知识（Wiki/API）是增强探索能力的重要手段
- **技能复用**：将成功行动抽象为可复用的"技能"（如 Voyager 的可执行代码存储）
