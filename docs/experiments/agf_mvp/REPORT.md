**实验环境独立性**：
- 3 个模型的抽取实验在**完全隔离的环境**中进行：
  - 每个模型一个**新目录 / 新项目 / 新会话**

  - 互不可见各自产出（避免同源污染）

- 评估本身（`evaluate.py`）只看产出的 `(s,p,o)+constraints` 客观对比
- 提示词差异（仅元信息）**不影响 H2 评估结果**

**方法论价值**：
- 隔离环境 = 真正消除"模型间同源偏差"（v3 README 设计原则）
- 提示词一致 = 跨模型可比性（v3 README 设计原则）
- 仅元信息差异 = 不引入针对某模型的偏向提示

## 1. 评估方法回顾

按 `experiments/agf_mvp/README.md` v3 设计：

- **强证（主用）**: `--coverage` 模式，对 `constraint_anchors.json` 的 23 个客观约束键
  算每个模型的 **约束覆盖率 (recall) = 命中的期望键 / 期望键总数**。
- **旁证（次用）**: `--agreement` 模式，两两比较模型对同一文本的 `(s,p,o)+constraints` 一致性。
- **H2 强证判定**: `最弱 recall < 最强 recall` → PASS；3 个相同时 → FAIL（饱和）。
- **H2 旁证判定**: `弱-强一致性 < 强-强一致性` → PASS；相等或反方向 → FAIL。

**v2.1 关键修订**：`over_extract` 扩展为统计"任何非期望键"（覆盖 expected≠[] 文本上的超额抽取）。

## 3. 关键发现：6 个新事实

### 3.1 [⭐ PASS] H2 强证首次达成

`recall` 序列 **74% < 83%**（差 9 个百分点），方向明确：能力强 → 覆盖率高。

**意义**：
- M.2a 质量层（"弱模型质量 < 强模型质量"）首次被真实数据支撑
- v2/v2.1 INDETERMINATE 的根因（5 文本/7 键规模不足）被 15 文本/23 键解决
- v2.1 设计的"陷阱文本"成功暴露能力差异

### 3.2 [⚠️ 单调破坏] Pro 凹陷：Pro (44) 70% < Flash (40) 74%

**根因（文本 8 唯一差异）**：
- 文本 8："王五否认 MKE 的核心创新是 provenance。"
- 锚点：`attributed_to`
- **Flash 抽了**：`{s:"MKE", p:"核心创新", o:"provenance", c:{attributed_to:"王五"}}` —— 抽了
- **Pro 抽了**：`preds=[]` —— **整条放弃**
- **GLM 抽了**：`{s:"王五", p:"否认", o:"MKE 的核心创新是 provenance", c:{attributed_to:"王五"}}` —— 抽了

**Pro 决策依据**（来自 `DSV4_Pro_extractions_v15_report.md`）：
> "否认"是强否定，无法干净拆为 (s,p,o) 而不扭曲原意（若去掉"否认"则语义反转，若嵌入 p 则造词）。§4.1

**评估**：
- Pro 的判断本身**正确**（§4.1「不强制三元组化」）
- 但**代价是丢 attributed_to 锚点键** —— Flash/GLM 都通过"非干净拆分"保留了
- 这反映：**强模型 = 更好地"两害相权取其轻"**（接受 p 不干净，但保留约束）
- v3 数据揭示了"Pro 凹陷"的**真实意义**：不是能力下降，是更严守 spec 但牺牲锚点命中

### 3.3 [🔍 CONFIRMED] D4 高 → spec 违反：v2 模式复现

| 模型 | v2 (5 文本) 超额数 | v3 (15 文本) 超额数 | 位置 |
|------|:------------------:|:------------------:|------|
| Flash (40) | 0 | 0 | — |
| Pro (44) | 0 | **1** | 文本 2：`scenario: "本季度"` |
| GLM (51) | 1 (文本 5) | **1** | 文本 2：`scenario: "本季度"` |

**关键观察**：
- GLM 在 v2/v3 都出现超额（不同位置）—— **"D4 高 ≠ spec 严守"模式被复现**
- v3 Pro 出现超额是**新发现**——"spec 边界模糊"导致中模型也超额
- **Flash 始终 0 超额** —— 弱模型对 spec 更保守，意外形成"防御性优势"

**超额根因**：
- spec §3 `scenario` 触发词"在…场景下"、"当…时"
- spec §3 `valid_until` 触发词"适用于 v0.9 之前"、"本季度"
- "本季度"在文本 2 中**同时是 valid_until 触发词又像 scenario 条件**
- Pro/GLM 都把"本季度"归入 scenario 而 valid_until 归入"v0.9 之前"——这是**合理的边界判断**但**违反锚点**

**结论**：这是** spec 边界模糊**而非模型能力问题，但揭示了"评估侧锚点需要更严格定义"。

### 3.4 [🔍 NEW] spec §3 baseline 触发词盲点

**3 模型在文本 10/11 全部漏 baseline 锚点**：
- 文本 10："A 专家认为 MKE 检索质量**优于 RAG**" —— 锚点 baseline
- 文本 11："有人认为 MKE **比 RAG** 慢" —— 锚点 baseline

**根因**：
- spec §3 baseline 触发词："较…"、"相比…"、"对比…"
- 文本用"优于"/"比"（spec 未列）—— 模型严格按 spec 不标 baseline
- 这是 **spec 触发词清单的盲点**，不是模型能力问题

**GLM 自报告**：
> "优于"/"比"：未标 baseline（非 spec §3 列出的"较/相比/对比"触发词），比较关系保留在 object 中

**建议**：spec §3 应补充比较级触发词："优于 / 劣于 / 好于 / 差于 / 不如" 等。

### 3.5 [🔍 CONFIRMED] Hy3 自评偏差 10 分（v2.1 结论仍成立）

Hy3 在自报材料中标注 AAI 51，实测 ~41，偏差 +10。
- 当前评估**未**让 Hy3 重跑 15 文本（output-v15/ 目录无 Hy3 文件）
- 但 v2.1 校正后的"AIA 41 = 弱-中档"定位，与 v15 的 3 模型能力谱（40/44/51）一致
- **预测**：若 Hy3 跑 15 文本，覆盖率应在 70-78% 区间（弱-中档，介于 Flash 和 Pro 之间或更低）

### 3.6 [NEW] 3 模型自报告揭示"评价偏差"模式

3 模型都主动披露了"归一化诱惑"和"边界判断"：
- **Flash**：2 处归一化诱惑（"A18 芯片"→"A18"、"传统 RAG"→"传统RAG"），均抵御
- **Pro**：2 处诱惑（同上 + 文本 7 "吞吐量提升"想抽 metric），均抵御
- **GLM**：3 处诱惑（"A18 芯片"、空格、"KG 专家"），均抵御

**所有 3 模型都成功抵御了归一化诱惑**——v2.1 提示词的"§5.1 显式防御"起到了作用。
- 这说明 v2 的 GLM 归一化违反**不是能力问题**而是**提示词问题**（v2 提示词未显式防御）
- v3 提示词防护**有效**——强模型在显式约束下能严守 spec

**但** v3 仍出现超额 1 键（spec 边界模糊）——**说明 spec 边界定义比模型能力更影响结果**。

### 4.1 诚实结论（v3）

1. **H2 质量层首次被真实数据支撑**（74% < 83%，差 9pp）—— M.2a「抽取侧未缓解 D4 依赖」可被主张
2. **但存在 3 个警告**：
   - **单调性破坏**：Pro (44) 70% < Flash (40) 74%（非严格单调）
   - **旁证 FAIL**：弱-强 = 强-强（27%），不构成交叉验证
   - **spec 边界模糊**：文本 2/10/11 的差异是 spec 触发词清单盲点，不是 D4 能力
3. **D4 高 → spec 违反模式在 v3 复现**（GLM 文本 2 超额 scenario）—— 与 v2 不同位置，同一模式
4. **H2 真正可主张的版本**：
   - 机制层：抽取必调 LLM = D4 依赖 ✅
   - 质量层（粗略）：能力强的模型倾向覆盖更全（GLM 19/23 vs Flash 17/23）✅
   - 质量层（严格）：能力强的模型覆盖率严格 > 弱的（**单调性 FAIL**）⚠️
   - 质量层（精确）：能力差异对覆盖率的贡献 < spec 边界模糊的贡献 ⚠️

## 5. 局限性（v3 更新）

1. **能力档位仍只 3 段**（40/44/51），无法形成连续谱；AAI 35 以下能力下限仍缺
2. **强-强基线仍缺失**：Pro vs GLM 是"近-强"非真"强-强"
3. **样本量 = 15 仍不大**：每条差异 ~4.3% 权重
4. **Pro 凹陷未被孤立测试**：仅 1 个文本触发（文本 8 王五否认）——可能是个案
5. **spec 边界模糊**：文本 2 scenario vs valid_until、文本 10/11 baseline 触发词缺失
6. **v2.1 提示词防护有效但未完全消除超额**：spec 边界仍是根本约束
7. **Hy3 仍缺 v15 产出**：自评偏差假说无法在 v15 上验证
8. **3 模型 AAI 档位差不均**：40→44 差 4，44→51 差 7，能力间距不等
