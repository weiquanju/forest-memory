# 断言抽取方法说明（Extraction Spec）

本说明定义「从文本抽取断言」的统一规范，供**不同模型**在相同标准下独立抽取，
使模型间的输出差异来源于**能力（D4）**而非**对格式/任务的理解差异**。
评估时只比较各模型抽取结果的一致性，不依赖任何 gold 标准。

---

## 1. 任务定义

输入一段文本，输出其中可被结构化的**断言（assertion）**列表。
每个断言是一个 `(s, p, o, constraints)` 四元组：

| 字段 | 含义 | 示例 |
|---|---|---|
| `s` (subject) | 主体实体 | `A18`、`MKE` |
| `p` (predicate) | 谓词 / 关系 / 属性 | `perf_gain`、`manufactured_by` |
| `o` (object) | 客体值或实体 | `30%`、`TSMC` |
| `constraints` | 限定条件的键值对（见 §3） | `{"scenario":"单核跑分"}` |

- 一句话可抽取出**多个**断言（如同时含关系断言与量化断言）。
- 一个 `(s,p,o)` 下可挂**多个**约束键。
- 抽取**必须严格基于文本显式信息**，不得推测、不得编造约束。

## 2. 输出格式

> 结构契约以 `extractions.schema.json` 为准（机器可读、权威）；以下 JSON 片段仅为人类速览，若与 schema 冲突以 schema 为准。

仅输出一个 JSON 数组，每个元素结构如下（不要输出解释文字）：

```json
[
  {"s":"A18","p":"perf_gain","o":"30%",
   "constraints":{"scenario":"单核跑分","baseline":"A17","metric":"Geekbench6"}}
]
```

- `constraints` 永远是一个对象；无约束时为空对象 `{}`。
- `s`/`p`/`o` 使用文本中的原词，不做归一化（如 `台积电` 不改写为 `TSMC`）。
- 若文本无可结构化的断言，输出空数组 `[]`。

## 3. 约束类型定义（constraints 的键）

| 键 | 含义 | 触发词示例 |
|---|---|---|
| `scenario` | 适用场景 / **非时间条件** | "在…场景下"、"当…时" |
| `baseline` | 对比基线对象 | "较…"、"相比…"、"对比…"、**"优于…"、"劣于…"、"好于…"、"差于…"、"不如…"、"比…"** |
| `metric` | 度量标准 | "（Geekbench6）"、"按…指标" |
| `valid_until` | 时效截止（含**显式时间限定**） | "适用于 v0.9 之前"、"本季度"、"今年"、"2027 年 6 月之前" |
| `attributed_to` | 观点归属 | "专家认为"、"据…称"、"某人认为/否认/反对/推翻/摒弃/怀疑" |
| `confidence` | 不确定性 | "可能"、"或许"、"缺乏实证"、"尚无实证" |

### 3.1 边界规则（v3.1 补充）

1. **时间短语优先归 `valid_until`**：含"本季度/今年/2027 年 6 月之前"等显式时间表述的约束键，必须归 `valid_until`，**不得**归 `scenario`（即使语义上像"适用条件"）
2. **比较级触发词归 `baseline`**：含"优于/劣于/好于/差于/不如/比"等比较关系词，比较对象（被比较方）必须归 `baseline`（如"MKE 优于 RAG" → baseline="RAG"）
3. **否定/推翻类动词必须标 `attributed_to`**：含"否认/反对/推翻/摒弃/怀疑"等强观点动词，必须同时标 `attributed_to`（即使主体已含归属人）
4. **`attributed_to` 触发词扩展**（v3.1）：除"专家认为/据…称"外，**所有含人名 + 观点动词**的表述都触发 `attributed_to`，包括但不限于："王五认为/否认/反对/推翻/摒弃/怀疑"、"李四认为"等

- 约束键**只取文本中实际出现的**；未出现的不填。
- 观点 / 不确定性类内容必须标 `attributed_to` 或 `confidence`，不得当作客观事实。
- 否定/推翻类断言必须保留否定语义（§4.1「不强制三元组化」不适用于此——可拆为 `(s, p, o, c)` 其中 p 含否定动词）。

## 4. 边界与质量准则

1. **不强制三元组化**：无法干净拆成 `(s,p,o)` 的内容，宁可不出该断言，也不强行扭曲。
2. **不推测**：文本未明说的约束（如未写的基线）不得补全。
3. **区分事实与观点**：带「专家认为 / 可能」的文本，必须落到 `attributed_to` / `confidence`。
4. **原词优先**：实体与值保留原文措辞，归一化（实体规范化 D8）不属于本抽取步骤。

---

## 5. 与各模型会话的配合流程

1. 模型读取本说明 + `test_texts.json` 中的 `texts` + **`extractions.schema.json`（类型契约）**。
2. 模型**仅依据文本**逐条抽取，产出 `preds`（不参考任何其他模型的输出）。
3. 产出文件**必须**符合 `extractions.schema.json` 的结构契约，速览如下：

```json
{
  "model": "<模型名 / AAI等级>",
  "samples": [
    {"text": "<原文>", "preds": [ {"s":"..","p":"..","o":"..","constraints":{..}} ]}
  ]
}
```

> 完整字段约束（必填项、类型、约束键取值）见 **`extractions.schema.json`**（类型文档）。
> 建议让模型产出后用 JSON Schema 校验器（如 Python `jsonschema`）自检，确保
> `model`/`samples`/`preds` 及每个 assertion 的 `s`/`p`/`o`/`constraints` 齐全且类型正确。

4. 评估：`python evaluate.py --agreement weak.json strong.json strong2.json`
   比较弱模型与强模型抽取的**一致性**；若有第二份强模型文件则作为强-强基线。
