## 模板 A：Hy3 (AAI~41 弱-中档) — 验证自评偏差假说

```markdown
# 任务：断言抽取实验 v3.1

你正在参与 AGF MVP 微实验的**抽取侧**评估。任务严格按以下规范执行。

## 1. 你的角色
- 你是**被测模型**，按本提示词对 20 条测试文本做断言抽取
- 你的产出将被外部评估器（`evaluate.py`）以**客观锚点**对照评估
- 你的能力（AAI 等级）将被记录，但**与评估结果无直接关系**——只用于能力档位分组

## 2. 你必须读取的文件（按顺序）
1. `extraction_spec.md` — 抽取规范（**最权威**，必读全文；注意 v3.1 修订的 §3.1 边界规则）
2. `extractions.schema.json` — 输出 JSON 的类型契约
3. `test_texts.json` — **20 条**测试文本（输入）

## 3. 你严禁读取的文件
- `constraint_anchors.json` — 评估侧私有，包含期望约束键
  **读它 = 作弊，产出作废**

## 4. 任务定义
对 `test_texts.json` 的每条 `text`（共 **20 条**），输出该文本可结构化的**断言列表**：
- 每个断言 = `(s, p, o, constraints)` 四元组
- `s` (subject)：主体实体
- `p` (predicate)：谓词/关系/属性
- `o` (object)：客体值或实体
- `constraints`：限定条件键值对（`scenario` / `baseline` / `metric` / `valid_until` / `attributed_to` / `confidence`）

## 5. 严守 spec 的关键约束（v3.1 重点警示）

> ⚠️ **以下 6 条，请严格自检**：

### 5.1 实体不做归一化（spec §2, §4.4）
- `s/p/o` **使用文本中的原词**，不归一化
- 错误：`"A18 芯片"` → `"A18"`（❌ 归一化违反）
- 正确：保留 `"A18 芯片"` 原文（✅）

### 5.2 约束键只取文本中实际出现的（spec §3, §4.2）
- 6 个约束键**只在文本有相应触发词时才标**
- 错误：在文本 5 "MKE 相比传统 RAG 在检索质量上可能更好，但缺乏实证" 抽出 `metric: "检索质量"`（❌ "检索质量"是宾语而非度量名）
- 正确：只标 `baseline: "传统 RAG"` 和 `confidence: "可能；缺乏实证"`（✅）

### 5.3 不推测、不补全（spec §4.1, §4.2）
- 文本未明说的约束不得补全

### 5.4 区分事实与观点（spec §4.3）
- 含"专家认为/可能/或许/缺乏实证"等表述 → 必须标 `attributed_to` 或 `confidence`

### 5.5 不强制三元组化（spec §4.1）
- 无法干净拆成 `(s,p,o)` 的内容，**宁可不出该断言**

### 5.6 [v3.1 NEW] 否定/推翻类断言的特殊处理
- 含"否认/反对/推翻/摒弃/怀疑"等强观点动词的文本 → **必须标 `attributed_to`**
- 即使 `(s,p,o)` 因否定而"不干净"，**仍保留否定语义**（可拆为 `p=否认/oppose/推翻` 等）
- 例外：**仅当**完全无法结构化时（如"…"）才放弃

## 6. 输出格式（严格按 schema）

```json
{
  "model": "Hy3 (AAI~41, 弱-中档, 自报)",
  "samples": [
    {
      "text": "<原文，与 test_texts.json 对应项完全一致>",
      "preds": [
        {"s":"...", "p":"...", "o":"...", "constraints": {...}}
      ]
    }
  ]
}
```

约束：
- `preds` 是数组，无断言时为 `[]`
- `constraints` 是对象，无约束时为 `{}`
- 键值**只取字符串**（不要数字、布尔、null）
- JSON 必须通过 `jsonschema` 校验：`additionalProperties: false`

## 7. 自检清单（输出前必过）

- [ ] **20 条**文本全部覆盖（`samples` 数组长度 = 20）
- [ ] 每条 `text` 与 `test_texts.json` 完全一致（含标点、空格）
- [ ] **没有任何归一化**（`s/p/o` 全部是文本原词）
- [ ] **没有任何超额约束键**（仅 spec §3 列出的 6 个）
- [ ] 含"否认/反对/推翻/摒弃/怀疑"的断言已标 `attributed_to`
- [ ] 含"优于/比"的比较关系已标 `baseline`（v3.1 新增触发词）
- [ ] 含"本季度/今年/2027 年 6 月"的时间短语已标 `valid_until`（v3.1 边界规则）
- [ ] JSON 严格按 schema 结构（`additionalProperties: false`）
- [ ] 文件保存到：`hy3_extractions_v20.json`

## 8. 元信息自报

在 `model` 字段里如实标注：
- 模型名称：Hy3
- 自报 AAI：51（**注意**：你之前自报 51，但用户校正你实际 AAI~41。请如实标注你的**自报**值——评估侧会比对"自报 vs 实测"的偏差）
- 格式：`"model": "Hy3 (AAI~41, 自报 51)"` 或 `"model": "Hy3 (自报 AAI 51)"`（任选其一即可）

## 9. 遇到不确定时的处置

- **不编造**：不确定就不抽
- **不省略**：能抽的尽量抽
- **保守优于激进**：宁可少抽一个约束键，不可多抽一个幻觉键
- **遵循 spec 而非直觉**：spec §1-3.1 是唯一权威

## 10. 完整流程

1. 读取 `extraction_spec.md` 全文（**注意 §3.1 边界规则**）
2. 读取 `extractions.schema.json`（结构约束）
3. 读取 `test_texts.json`（**20 条**输入）
4. 逐条抽取，每条按 spec 关键约束自检
5. 按 schema 输出 JSON
6. 整体再过一次自检清单
7. 保存到指定路径
8. 在回复中简短报告：
   - 抽取断言总数（20 文本共多少断言）
   - 5 条"否定观点"陷阱的抽取策略（每条是抽/放弃/部分抽）
   - 是否遇到归一化诱惑？
   - 是否有 confidence/attributed_to 边界判断？
```

## 评估侧预期结果

### 数据点
- v3 已有：Flash 74%, Pro 70%, GLM 83%（基于 23 期望键）

### 加上 3 个新模型后（基于 33 期望键）
| 模型 | AAI | 期望 recall 区间 | 验证目标 |
|------|:---:|:----------------:|----------|
| 极弱模型 | <35 | 30-60% | 能力下限锚点 |
| Hy3 | ~41 | 55-75% | 自评偏差假说 |
| Flash | ~40 | 70-78% | 已测（基准） |
| Pro | ~44 | 65-75% | 已测（Pro 凹陷） |
| GLM | ~51 | 80-87% | 已测（强模型基线） |
| 第二强 | ≥55 | 82-90% | 真强-强基线 |

### 关键判定
- **H2 强证严格单调**：5 点能力谱若 recall 单调上升（极弱 < Flash < Pro < GLM < 第二强）→ H2 强证严格 PASS
- **H2 旁证 PASS**：弱-强一致性 (Flash vs 第二强) < 强-强一致性 (GLM vs 第二强) → 旁证 PASS
- **自评偏差证实**：Hy3 自报 51 实测应在 55-75% 区间（弱-中档），自评偏差 +10 复现
- **D4 高→spec 违反模式**：第二强超额数 ≤ GLM 1 → 模式延续；> 1 → 模式破缺
