## 2. 维度评分与详细分析

### D1: 引用真实性 — **8/10**

| 检查项 | 结果 |
|--------|------|
| 引用清查 | 所有叶子中均明确标注引用来源 |
| 虚构引用 | 未发现明显虚构引用 |
| arXiv ID 使用 | 正确标注 arXiv ID（如 Mem0: arXiv:2504.19413, ToG: arXiv:2307.07697） |
| DOI 使用 | 未使用 DOI |
| 待验证引用 | 约 5-8 处引用需手动验证（如 Hu et al. 2025 的三维分类框架引用 arXiv:2512.13564） |

**正面**: 无明显虚构引用。arXiv ID 标注一致。**不足**: 部分引用只写 arXiv ID 未标注年份和作者名。一些非 arXiv 来源（如行为实验经典引用）未涵盖——这个问题属于资料本身的特征，非模型能力问题。

### D2: 引用准确性 — **7/10**

| 检查项 | 问题率 | 说明 |
|--------|:-----:|------|
| 作者完整性 | 10% | Mem0 的作者为 "Chhikara et al." 但缺少完整名单 |
| 年份准确性 | 5% | 基本准确 |
| 标题准确性 | 10% | 标题与内容基本一致 |
| 引用语境恰当性 | 15% | 部分引用的语境略有偏差。如 Gershman et al., 2025 在 CLS 与 KV 对比处的引用语境可更精确 |
| 格式一致性 | ✓ | YAML refs 格式一致 |

**正面**: 引用元数据基本准确。方法对比表中的论文标题与内容对齐良好。**不足**: 语境恰当性方面存在改善空间——部分引用放在对应内容中但缺乏对该引用具体贡献的说明。

### D3: 层级组织质量 — **8/10**

| 评估项 | 评分 |
|--------|:---:|
| Tree 划分合理性 | 9/10 — 3 棵树的划分逻辑清晰，从生物→工程→应用的递进关系自然 |
| Branch 覆盖完整性 | 8/10 — T2 仅 3 个枝干略少，Agent 应用场景未独立成枝干 |
| Leaf 单一职责 | 8/10 — 大多数原子聚焦单一主题 |
| 命名规范一致性 | 7/10 — 命名使用长描述性名称（如 `memory-operations-writing-reading-management.md`），与 index 中展示的名称不一致 |
| refs 连通性 | 9/10 — 跨树引用关系明确，无孤立节点 |

**正面**: 森林结构逻辑清晰，生物→工程→应用的递进关系安排合理。跨树引用图很好地展示了 CLS→Agent 分类、KV→记忆读取等关键映射。**不足**: T2 只有 3 个枝干，Agent 应用场景仅 1 个叶子，覆盖不够全面（对比输入资料的广度而言）。命名风格偏长，索引文档中使用短名，导致不一致。

### D4: 批判性分析深度 — **5/10**

| 评估项 | 评分 | 说明 |
|--------|:---:|------|
| 论述深度 | 5/10 | 部分原子止于"方法简介+性能数据"层面 |
| 横向对比 | 6/10 | Mem0/MemVerse/DYNA 对比表很好，ToG/PoG/SoG 对比也不错 |
| 局限性讨论 | 5/10 | 部分叶子有"开放问题"章节，但缺失一半以上的叶子 |
| 张力呈现 | 4/10 | CLS vs KV 的张力讨论较好，但其他地方缺乏 |
| 可操作洞见 | 4/10 | 趋势观察 ("经验跟随属性尚未被系统解决") 是亮点但少见 |

**正面**: ToG/PoG/SoG 对比中提到了搜索效率瓶颈（10^6 节点级延迟超 30 秒），这是量化局限性的好例子；Mem0/MemVerse/DYNA 的对比表列出了各框架的主要局限。**不足**: 整体偏"陈述"而非"分析"。T1 的大部分原子缺少横向对比和批判性讨论。与之前的 dsv4pro 基线评测 (4/10) 相比有所提升。

### D5: 学术规范性 — **6/10**

| 评估项 | 评分 | 说明 |
|--------|:---:|------|
| 方法论声明 | 5/10 | 无方法论声明 |
| 引用格式一致性 | 7/10 | YAML refs 格式一致但部分缺少年份/作者 |
| 版本标识 | 5/10 | 部分叶子缺失 version/updated 字段 |
| 元数据完整性 | 6/10 | 有 tree/branch/leaf 但部分少了 version |
| .experiment_metadata | 5/10 | 缺失抽取参数（max_atoms_per_doc, temperature）和 model_name 字段；tool_version 为模糊的 "4.x" |

**正面**: YAML frontmatter 结构基本完整，org 字段在代码和组织元数据存在。**不足**: `.experiment_metadata.yaml` 不完整——缺失 `experiment_id`、`model_name`、`extraction_params` 等关键字段。forest/index.md 的 frontmatter 缺少 `experiment` 和 `model` 字段。tool_version 填写为 "4.x" 不够精确。
