# 断言图与知识无损压缩

## 压缩什么

知识无损压缩的目标不是压缩文本字节数——那是 gzip 的事。压缩的对象是**断言冗余**：

| 冗余类型 | 示例 | MKE 能否检测 |
|---------|------|:---:|
| 同一断言的重复表述 | "巴黎是法国首都" / "法国首都是巴黎" / "Paris is the capital of France" | ❌ 需要 D4 判断语义等价 |
| 蕴含冗余 | "A18 性能提升 30%" 蕴含 | ❌ 需要逻辑推理 |
| 上下文膨胀 | "根据加州大学 2023 年发表在 Nature 的一项研究，A18 性能提升 30%" → 核心断言只有 10 字 | ❌ 需要事实提取 |

**MKE 能做的是组织文档，不能做的是从文本中提取并合并等价断言。** 断言图解决的就是后者。

## 为什么断言图能做到 MKE 做不到的事

```
MKE 的交叉声明检测（文本去重）：
  "iPhone 16 采用了 A18 芯片" vs "苹果最新手机搭载新一代处理器"
  → 需要 D4 批判性分析判断语义等价
  → AAI 40: D4=3.0 → 不可靠
  → AAI 51: D4=7.5 → 有 25% 不确定性

断言图的结构化去重：
  uses_chip(iPhone16, A18) vs uses_chip(iPhone16, A18)
  → 字符串比较即可
  → 不需要 LLM
  → 从根本上解决了 D4 能力瓶颈
```

**关键洞察**：文本去重的困难在于语言理解。断言图把问题先转化成结构化表示 (s,p,o)，去重变成了结构化匹配——能力要求从 D4（批判性分析）降到了字符串比较。

## 完整流程

```
原始文本 → 断言提取 → 断言去重 → 规范表示 → 训练数据再生

Step 1: 断言提取
  "iPhone 16 采用 A18 芯片，性能较上代提升 30%"
  → [
      {s: iPhone16, p: uses_chip, o: A18, conf: 0.95},
      {s: A18, p: perf_gain_vs_prev, o: 30%, conf: 0.90}
    ]

Step 2: 断言去重
  100 篇文章提取出相同的 {iPhone16, uses_chip, A18}
  → 只保留 1 条断言，附带 source_count: 100

Step 3: 再生（输出给外部 NLG 系统）
  从断言图生成多样化训练文本
  → 每次生成不同表达，保持语言多样性
```

**关键边界**：步骤 3（断言→文本再生）不在 MKE 范围内——MKE 负责确保断言图的质量，消费方决定如何消费。

## 为什么此路径更可行

| 要素 | 状态 | 说明 |
|------|:---:|------|
| 断言提取 | ⚠️ 接近可用 | AAI 51+ 的实体关系抽取准确率已较高，但细粒度事实提取仍有挑战 |
| 断言去重 | ✅ 理论成熟 | (s,p,o) 直接比较，比语义文本去重简单一个数量级 |
| 规范表示 | ✅ 理论成熟 | RDF/OWL 标准可直接复用 |
| 再生质量 | ⚠️ 需要验证 | 生成能力下限有保障（LLM 生成），上限（能否匹敌原文多样性）未知 |
