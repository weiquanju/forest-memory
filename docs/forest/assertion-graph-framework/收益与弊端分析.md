# 收益与弊端分析

## 五项核心收益

### 收益 1：治理粒度下沉——精准定位而非株连

```
当前 MKE：
  Leaf 含 10 个事实，1 个是错的
  → 整篇 quality 受影响
  → 无法精确定位问题

断言级 MKE：
  同篇 Leaf → 10 条 Assertion
  → 错误那条 conf=0.3，标记为待验证
  → 其余 9 条 conf≥0.9，正常使用
```

一个低质量事实不再拖累整篇文档。

### 收益 2：冲突检测从语义变为逻辑

```
断言级：
  {A18, perf_gain, 30%} vs {A18, perf_gain, 25%}
  → (s,p) 相同，o 不同 → 直接检测到冲突
  → 不需要 LLM
```

> 原理详见 [断言图与知识无损压缩](断言图与知识无损压缩.md) §"为什么断言图能做到 MKE 做不到的事"——结构化 (s,p,o) 匹配替代语义判断，不再需要 D4 批判性分析。

### 收益 3：检索精度跃升

```
当前：返回完整 Leaf（800 字，含答案也含无关内容）
  Query: "A18 芯片由谁代工？"
  → 返回整篇 Leaf → Agent 浪费 ~95% 上下文窗口

断言检索：返回精确断言 + 可选完整 Leaf
  Query: "A18 芯片由谁代工？"
  → 返回 {A18, manufactured_by, TSMC, conf: 0.97, source_count: 28}
  → Agent 得到精确答案
  → 如需语境，再拉取完整 Leaf
```

### 收益 4：知识可计算性

```sql
-- 当前 MKE 无法回答：
-- "哪些芯片同时由 TSMC 和 Samsung 代工？"
SELECT DISTINCT a1.subject
FROM assertion a1
JOIN assertion a2 ON a1.subject = a2.subject
WHERE a1.predicate = 'manufactured_by' AND a1.object = 'TSMC'
  AND a2.predicate = 'manufactured_by' AND a2.object = 'Samsung';
```

文档库做不到，断言图可以。

### 收益 5：source_count 作为新质量信号

```
{A18, perf_gain, 30%}:
  source_count=47 → 被 47 篇独立文档确认 → 高可信
  source_count=1  → 仅在一篇文档中出现 → 需验证
  source_count=0  → LLM 自行推断的 → 高风险的"潜知识"
```

这是 MKE 当前完全没有的质量维度。

## 五项弊端与缓解

### 弊端 1：去语境化风险

```
原文："在单核跑分场景下，A18 性能提升 30%"
断言：{A18, perf_gain, 30%}  ← "在单核跑分场景下" 丢了

如果在多核场景下引用此断言 → 事实错误
```

**缓解**：`constraints` 字段携带条件约束——但这将问题推给了约束条件提取，一个比 (s,p,o) 抽取更难的任务。

### 弊端 2：知识碎片化——叙事结构被破坏

```
Leaf "A18 芯片性能分析" 的原始结构：
  背景 → 跑分数据 → 对比竞品 → 工艺分析 → 结论

断言化后：
  5 条无关联的 (s,p,o) 三元组
  → 丢失了"为什么是这个结论"的推理链
```

**缓解**：文档适合人类理解，断言适合机器处理。通过 Fact Cluster 保持语义内聚性，但叙事链的损失不可完全避免。

### 弊端 3：抽取误差的级联放大

```
当前：抽取错误 → 一篇 Leaf 受影响 → 影响范围有限

断言级：
  抽取错误 → 一条错误断言进入 Assertion 表
  → source_count 虚假累积（被后续匹配"确认"）
  → 被多个下游消费方引用
  → 错误被放大
```

**缓解**：单点错误的影响半径随断言图连通度增长。需要源文本回溯验证机制。

### 弊端 4：实体规范化——被低估的硬问题

```
"iPhone 16" = "iPhone16" = "苹果 16" = "Apple iPhone 16" = "iphone-16"？

如果实体规范化失败：
  {iPhone16, uses_chip, A18}    ← 断言 1
  {iPhone_16, uses_chip, A18}   ← 断言 2 被当成不同断言
  → source_count 各为 1，而非正确的 2
```

**缓解**：这是 KG 领域经典难题，MKE 将不可避免地面对。需要实体解析流水线。

### 弊端 5：表达力受限

```
适合 (s,p,o)：
  "A18 由 TSMC 代工" / "iPhone 16 售价 5999 元"

不适合 (s,p,o)：
  "内存带宽是 AI 推理的主要瓶颈，而非算力"
  "Rust 的所有权模型从根本上改变了系统编程的安全范式"
```

**缓解**：不是所有知识都需要断言化。不适用的知识保留在 Leaf.content 中，不强制提取断言。治理粒度不一致是刻意接受的设计权衡。
