# 时序断言与溯源链

## 时序断言

### 时间维度的必要性

```
静态断言：{Twitter, CEO, Elon Musk}         ← 不再成立
时序断言：{Twitter, CEO, Elon Musk,
           valid_from: 2022-10, valid_until: 2023-06}

检索时：
  Query: "Twitter CEO 是谁？"（2024=>）
  → 不返回已过期断言（或标记为"曾担任"）
  
  Query: "Elon Musk 担任过 Twitter CEO 吗？"
  → 返回历史断言，附带 valid_until
```

### 表结构扩展

```sql
-- assertion 表增加时间字段
ALTER TABLE assertion ADD COLUMN valid_from TEXT;   -- ISO 8601
ALTER TABLE assertion ADD COLUMN valid_until TEXT;  -- null 表示当前仍有效
ALTER TABLE assertion ADD COLUMN is_current BOOLEAN DEFAULT TRUE;

-- 断言替代关系表（记录知识的版本演化）
CREATE TABLE assertion_supersedes (
    id              TEXT PRIMARY KEY,
    old_assertion_id TEXT NOT NULL,
    new_assertion_id TEXT NOT NULL,
    reason          TEXT,           -- "factual_correction" | "temporal_expiry" | "refinement"
    superseded_at   TEXT,
    FOREIGN KEY (old_assertion_id) REFERENCES assertion(id),
    FOREIGN KEY (new_assertion_id) REFERENCES assertion(id)
);
```

### 与 MKE"永不删除"原则的衔接

```
KG 的做法：
  {Twitter, CEO, Elon Musk} → 过期 → 删除或覆盖
  
MKE 的做法：
  {Twitter, CEO, Elon Musk, valid_until: 2023-06}     ← 保留
  {Twitter, CEO, Linda Yaccarino, valid_from: 2023-06} ← 新增
  assertion_supersedes: old→new, reason: 'temporal_expiry'
```

知识演化历史被保留。对 LLM 来说，知道"Elon Musk 曾任 Twitter CEO"和知道"Elon Musk 是 Twitter CEO"的区别很重要。

### 与 bim 森林的呼应

`跨森林知识注入与架构细化.md` 中 `temporal_rel` 字段（before/after/during）是时序断言的雏形。时序断言将其从"引用关系的一个可选描述"升级为"断言本身的一等属性"。

## 溯源链（Provenance Chain）

### 设计

```sql
-- assertion 表增加溯源字段
ALTER TABLE assertion ADD COLUMN source_samples TEXT;
-- JSON 数组，记录来源原文片段
-- [{"leaf_id": "xxx", "offset": 142, "text": "...提升 30%..."}, ...]

ALTER TABLE assertion ADD COLUMN extraction_model TEXT;
-- "GLM-5.2 (AAI 51)"

ALTER TABLE assertion ADD COLUMN extraction_confidence REAL;
-- LLM 自评的提取置信度（独立于事实置信度）
```

### 溯源链的意义

```
断言：{A18, perf_gain, 30%, conf: 0.90}
  ├── source_count: 47
  ├── source_samples: [
  │     {leaf: "xxx", text: "A18 单核性能提升 30%"},
  │     {leaf: "yyy", text: "单核测试中较上代提升约三成"},
  │     ...
  │   ]
  ├── extraction_model: "GLM-5.2 (AAI 51)"
  └── extraction_confidence: 0.92
```

这使 MKE 六维度优势之一的"可追溯性"从文档级下沉到事实级：
- 发现一条断言有问题 → 追溯到哪篇文档的第几行 → 追溯到哪个模型的哪次抽取
- 模型升级后 → 对比新旧模型的 extraction_confidence，量化抽取质量提升

### 溯源链与"永不删除"的协同

```
断言被修正时：
  old: {A18, perf_gain, 30%, valid_until: 2025-01}
  new: {A18, perf_gain, 28%, valid_from: 2025-01}
  
  assertion_supersedes 记录修正关系
  old.source_samples 保留原始来源
  new.source_samples 指向新的验证来源
  → 完整的知识演化史可被追溯
```
