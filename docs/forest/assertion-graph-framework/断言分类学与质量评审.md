# 断言分类学与质量评审

## 断言分类学

不是所有断言同质。不同断言类型需要不同的冲突检测策略和 confidence 模型：

| 断言类型 | 示例 | 特点 | 冲突检测方式 |
|---------|------|------|------------|
| **事实型** | "A18 由 TSMC 代工" | 可验证的真伪判断 | (s,p,o) 精确匹配 |
| **量化型** | "性能提升 30%" | 需要 baseline + metric 约束 | o 的数值比较 + 容差判断 |
| **时效型** | "截至 2024 年，iPhone 市场份额 28%" | 需要 temporal validity | 时间窗口交叉判断 |
| **关系型** | "A18 是 M4 系列的一部分" | 需要层级关系定义 | 图一致性验证 |
| **观点型** | "分析师认为 iPhone 17 将采用 2nm" | 需要归属来源 | 同一来源下的逻辑一致性 |

### 量化型断言的特殊处理

```
{A18, perf_gain, 30%}
  需要携带:
    baseline: A17
    metric: "Geekbench 6 单核"
    scenario: "单核跑分"  ← 来自 constraints 字段

冲突检测：
  {A18, perf_gain, 30%, baseline: A17, metric: Geekbench6}
  {A18, perf_gain, 25%, baseline: A17, metric: Geekbench6}
  → 检测到冲突（同 baseline + 同 metric + 不同 o）
  
  {A18, perf_gain, 30%, metric: Geekbench6}
  {A18, perf_gain, 15%, metric: SPECint2017}
  → 不冲突（不同 metric，不可直接比较）
```

### 观点型断言的特殊处理

```
{分析师_X, predicts, {iPhone17, uses_process, 2nm}, conf: 0.60}

观点不追求真值验证——追求：
  1. 来源一致性（同一分析师不能同时预测 2nm 和 3nm）
  2. 时效性（旧的预测可能已被证实/证伪）
  3. source_count 含义不同（多个分析师独立预测 → 加强置信度）
```

## 断言质量评审体系（D6-D8）

在 MKE 现有的 5 维度评审体系之外，增加断言专属的评审维度：

| 新维度 | 评估内容 | 评分标准 |
|--------|---------|---------|
| **D6 断言保真度** | 断言与源文本的语义一致性——有无去语境化偏差 | 0% 偏差 = 9-10 |
| **D7 提取精确率** | (s,p,o) 三元组各字段的提取准确率 | 0% 错误 = 9-10 |
| **D8 实体规范化率** | 同类实体是否使用统一的 canonical ID | ≥95% 规范化 = 9-10 |

### D6-D8 与 D1-D5 的关系

```
D1-D5（文档级评审）：评估 Leaf 的整体质量
D6-D8（断言级评审）：评估 Assertion 的提取和规范化质量

两者正交配合：
  Leaf D1=9 + Assertion D6=6 → 原文质量高，但断言抽取有严重去语境化
  Leaf D4=4 + Assertion D7=9 → 原文分析浅，但断言提取格式准确
```

## 此方向的研究优先级

| 子方向 | 优先级 | 理由 |
|--------|:---:|------|
| 断言分类学 | **P0** | 不同类型断言的冲突检测逻辑完全不同，是断言层正确性的基础 |
| D6/D7 评审维度 | P1 | 断言抽取出错率高时，整个断言层的价值归零 |
| D8 实体规范化 | P1 | 不解决则 source_count 不可信 |
| 量化型特殊处理 | P2 | 依赖约束条件提取的成熟度 |
