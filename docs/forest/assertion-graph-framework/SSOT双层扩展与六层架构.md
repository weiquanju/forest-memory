# SSOT 双层扩展与六层架构

## SSOT 双层机制

### 第一层：文档级 SSOT（已有）

```
Leaf A 和 Leaf B 重复声明同一标准
  → 向量相似度 > 0.80 → LLM 判定 → 拒绝写入 + 引用建议
  → 治理对象：整篇文档
  → 核心技术：向量嵌入 + LLM 语义判断
```

### 第二层：断言级 SSOT（新增）

```
Assertion {iPhone16, uses_chip, A18} 已存在
  → 新文本产生相同 (s,p,o)
  → UNIQUE INDEX 拦截 → source_count += 1，不新增行
  → 若 confidence 差异 > 阈值 → 触发冲突仲裁
  → 治理对象：单个事实
  → 核心技术：结构化字符串匹配
```

> 断言级 SSOT 为什么不需要 D4，参见 [断言图与知识无损压缩](断言图与知识无损压缩.md) §"为什么断言图能做到 MKE 做不到的事"——核心原理是 (s,p,o) 结构化匹配替代语义判断。

## 更新后的边界声明

| MKE 做 | MKE 不做 |
|--------|---------|
| 精炼知识的**组织**（层级、分类、atom_type） | ETL/数据管道 |
| 知识**质量校验**（**双层 SSOT**，扩展到断言级） | 大规模去重（MinHash/LSH 级） |
| 知识**版本回溯** | 格式转换 |
| 知识**一致性追踪**（**延伸到断言级**） | 向量数据库 |
| 知识**检索质量保障** | Agent 行为管理 |
| 知识**生命周期管理** | 全文搜索引擎 |
| **新增：断言提取与去重** | **新增：断言→文本再生（NLG）** |
| 作为知识质量治理层被消费 | 成为 RAG/Agent 框架本身 |

**关键边界**：MKE 不做断言→文本再生。这是训练数据管道的职责，不是知识质量基础设施的职责。

## 六层架构总图

```
┌─────────────────────────────────────────────────────────┐
│  Layer 5：治理与校验层                                【扩展】 │
│  三层冲突检测（文档级 + 断言级）+ 断言冲突仲裁协议          │
├─────────────────────────────────────────────────────────┤
│  Layer 4：持久化与记忆融合层                          【不变】 │
│  四类记忆 + Consolidation Pipeline + 容量管理              │
├─────────────────────────────────────────────────────────┤
│  Layer 3：混合检索引擎层                              【不变】 │
│  五阶段检索（向量+图+裁决+防溢出+可追溯）                   │
├─────────────────────────────────────────────────────────┤
│  Layer 2：知识构建与图索引层                          【扩展】 │
│  Forest/Tree/Branch/Leaf + assertion 表 + fact_cluster 表  │
│  + 双层 SSOT（文档级 + 断言级）                            │
├─────────────────────────────────────────────────────────┤
│  Layer 1：数据接入与归一化层                          【扩展】 │
│  知识原子（.md）+ 原始文本 → 统一为 Leaf + Assertions       │
├─────────────────────────────────────────────────────────┤
│  Layer 0：原始数据接入与断言抽取层                    【新增】 │
│  Assertion Extractor + Assertion Deduplicator             │
│  → 结构化 (s,p,o,conf) + source_count                    │
└─────────────────────────────────────────────────────────┘
```

## 影响评估

| 维度 | 影响 |
|------|------|
| **MKE 定位** | 仍是 AI 知识质量基础设施——治理粒度从文档下沉到事实 |
| **SSOT 能力** | 从"需要 LLM 的语义判断"扩展到"不需要 LLM 的结构化匹配" |
| **冲突检测** | O(n²) 全量比较 → O(k²) 簇内比较（k = 簇数量 << n = 断言总数） |
| **论文差异化** | 文档级→断言级的治理粒度下沉是无人覆盖的方向 |
| **工程复杂度** | +30-40%（新增断言表、抽取器、去重器） |
| **MVP 时间线** | 在已有 Leaf→SQLite 导入能力基础上，加断言层估计 4-6 周 |
