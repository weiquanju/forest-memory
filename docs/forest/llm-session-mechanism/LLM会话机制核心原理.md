# LLM 会话机制核心原理

## 知识声明

> 本知识原子基于**公知学术原理**（Transformer 架构，Vaswani et al., 2017）编写。不包含任何特定模型的专有实现细节。DeepSeek V4 Pro 的具体工程实现不在此讨论范围。

## 五步核心流程

### 1. 分词（Tokenization）

用户输入的文本首先被拆分为 token：

```
输入："你好，请帮我分析 MKE"
↓ tokenizer
Token 序列：["你", "好", "，", "请", "帮", "我", "分析", "MKE"]
```

**关键特性**：
- 一个中文字通常对应 1-2 个 token
- 一个英文单词通常对应 1-3 个 token
- 中英混排时 token 数可能比字符数多
- 同一语义的不同语言表述，token 数可能差异显著

### 2. 上下文窗口

整个对话的所有 token 组成一个序列：

```
[System Prompt tokens]              ← 固定开销
[第 1 轮对话 tokens]                 ← 累积增长
[第 2 轮对话 tokens]                 ← 累积增长
...
[第 n 轮对话 tokens]                 ← 累积增长
[当前用户输入 tokens]                 ← 最新
[正在生成的回复 tokens]              ← 逐 token 追加
```

上下文窗口有硬性上限（公开资料显示 DeepSeek 系列为 128K-1M token 量级）。当超出上限时，最早的内容被截断。

### 3. 注意力机制（Attention）

每个 token 在生成时会"关注"上下文中的所有 token：

```
注意力计算（简化）：
  Query（当前 token）· Key^T（所有历史 token）→ 相似度分数
  → softmax 归一化 → 注意力权重
  → × Value（所有历史 token 的内容表示）→ 加权融合
```

**核心特性**：
- **不是"搜索"或"回忆"**——是数学上的加权融合
- 注意力是全局的：每个 token 理论上能看到所有历史 token
- 但计算代价随上下文长度平方级增长（O(n²)）

### 4. 自回归生成

LLM 不是一次性"想出"整个回复。生成是逐 token 的循环：

```
生成流程：
  1. 基于当前上下文 → 预测下一个 token（概率分布）
  2. 选择概率最高的 token（或按温度采样）
  3. 将选中的 token 追加到上下文末尾
  4. 基于新的上下文 → 预测再下一个 token
  5. 重复直到生成结束标记（EOS token）

这是一个循环，不是一次性计算。
```

### 5. System Prompt

在用户的第一条消息之前，会插入系统指令。从架构角度看：

- System Prompt 和用户消息**在注意力机制中没有区别**
- 都是上下文窗口中的 token，都会被"关注"
- System Prompt 的长度直接占用上下文窗口

**为什么上下文超限时模型行为不稳定？**

因为 System Prompt（行为规则、工具定义）可能被最早挤出上下文窗口。模型丢失了"我是谁""我能做什么"的指令——但这不是"模型变笨了"，而是注意力无法再关注到这些指令 token。

## 与人类记忆的关键差异

| 人类记忆 | LLM 会话机制 |
|---------|------------|
| 学习改变突触权重（参数） | 参数冻结——学习不会改变模型 |
| 新记忆被"写入"神经网络 | 上下文窗口中的 token 序列——对话关闭后消失 |
| 长期记忆通过巩固永久存储 | 无法在对话间保留信息 |
| 注意力是神经生物学机制 | 注意力是数学上的加权求和 |
