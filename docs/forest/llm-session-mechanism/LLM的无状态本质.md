# LLM 的无状态本质

## 什么是无状态

每次对话，LLM 的模型参数（权重）不改变。

```
对话中：
  [用户] 巴黎是法国首都吗？
  [LLM] 是的。
  [用户] 记住：巴黎的首都身份有争议。
  [LLM] 已记录。

对话关闭 → 参数不变 → "巴黎有争议"消失

下一轮对话：
  [用户] 巴黎是法国首都吗？
  [LLM]（从预训练权重回答）是的。

你教了 LLM 的东西消失了。
```

这和人类的记忆机制有本质区别。人类学习时，突触的 LTP/LTD 会改变神经连接强度——这是**参数的改变**。LLM 做不到这一点。它的参数在训练完成后是冻结的。

## 上下文窗口截断的三种策略

当对话超出上下文窗口上限时，需要有策略决定哪些内容被保留：

| 策略 | 机制 | 丢失什么 |
|------|------|---------|
| 滑动窗口 | 保留最近的 N 个 token | 最早的内容——包括 System Prompt 的末尾 |
| 关键帧保留 | 保留 System Prompt + 最近的对话 | 中间的讨论内容 |
| 语义压缩 | LLM 自行摘要旧内容 | 精确的措辞和细节 |

### 最坏情况：System Prompt 被挤出

```
[System Prompt]  ← 定义了我的行为规则
[超长的历史对话]
[超长的历史对话]
[超长的历史对话]  ← 上下文窗口上限
[当前输入]        ← 只看得见这之后的 token
```

当 System Prompt 被挤出上下文窗口 → 模型遗忘行为约束 → 不能准确描述这个场景的具体表现。

## 现有缓解手段

| 手段 | 解决什么 | 不解决什么 |
|------|---------|---------|
| 人类复制粘贴历史对话 | 跨对话的信息传递 | 信息质量——复制粘贴可能带入错误 |
| RAG（从外部文档库检索） | 让 LLM 访问超出训练数据的知识 | 检索质量——被检索的文档可能冲突、过时、不完备 |
| Agent Memory（Mem0、MemVerse） | 记录跨对话的交互经验 | 知识治理——存的可能是错的、冲突的、过时的 |

### 现有手段的根本缺陷

所有现有手段解决的是**"怎么记住"**——

```
Mem0：存交互记录 + 检索
MemVerse：双区架构 + 持续巩固
RAG：文 chunk → 向量检索 → 注入
```

但**没有一个解决"记住的对不对"**：

```
知识 A 和知识 B 矛盾了 → 两个都存进去 → 两个都检索出来 → LLM 拿到矛盾信息
知识 C 已经过时了 → 仍然被检索 → LLM 基于过时信息回答
知识 D 是从一个不可靠来源来的 → 没有标记 → LLM 当作可靠知识使用
```

## LLM 会话局限的五维度拆解

| 局限 | 根因 | 架构层解决方案 | MKE 外挂解决方案 |
|------|------|:---:|:---:|
| 对话间无记忆 | 参数冻结 | 需要训练时改变架构 ❌ | ✅ 持久化 + 按需检索 |
| 上下文窗口有限 | 注意力代价 O(n²) | 更高效的注意力 ✅ | ✅ 渐进式检索 |
| 知识可能冲突 | 无内置冲突检测 | 需要架构级改动 ❌ | ✅ SSOT + 三层冲突检测 |
| 知识可能过时 | 无生命周期管理 | 需要架构级改动 ❌ | ✅ 状态机 + 永不删除 |
| 知识无法溯源 | 无内置引用追踪 | 需要架构级改动 ❌ | ✅ refs 引用链 + provenance |
