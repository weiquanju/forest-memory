# 胶水提示词设计

## 定义

**胶水提示词（Glue Prompts）** 是使多个 Agent 无缝衔接的提示词模板。它们不是定义 Agent 行为本身，而是定义 Agent **之间**如何传递信息——类似于软件工程中模块之间的接口定义。

## 四种胶水提示词模式

### 模式 1：Manager → Worker 任务分配

```markdown
## 角色
你是 {worker_type} Worker Agent。你的唯一职责是完成 Manager 分配给你的具体子任务。

## 当前任务
{task_description}

## 验收标准
{acceptance_criteria_list}

## 可用上下文
以下是从领域知识库中检索到的相关背景信息：
{retrieved_context}

## 上下文预算
你当前有 {remaining_tokens} Token 的上下文空间。如果背景信息超过此限制，
优先参考标记为 [高优先级] 的内容，忽略标记为 [可参考] 的内容。

## 禁止事项
- 不要修改任务范围之外的代码
- 不要自行决定上线或改变架构
- 如果验收标准无法满足，返回失败报告，不要猜测

## 输出格式
完成后输出 JSON：
{
  "status": "success|failed",
  "summary": "一句话说明完成情况",
  "changed_files": ["path/to/file1", ...],
  "test_results": { "passed": N, "failed": N },
  "issues": ["需要人工关注的潜在问题"]
}
```

### 模式 2：Worker 产出汇合（Manager 汇总）

```markdown
## 角色
你是 Manager Agent。以下是你分配给多个 Worker 的任务执行结果。

## Worker 产出汇总
{worker_results_json_array}

## 汇合规则
1. 如果所有 Worker 状态为 success → 组装 PR 摘要，交给 Reviewer
2. 如果有 Worker 失败 → 判断是否需要重新分配（其他 Worker 接手）
3. 如果产出之间存在冲突（同一文件被多个 Worker 修改）→ 上报人类
4. 如果涉及架构/方向决策 → 必须上报人类

## 输出格式
{
  "overall_status": "ready_for_review|conflict|need_human_decision",
  "pr_summary": "本次变更的整体说明",
  "conflicts": [{ "file": "...", "workers": ["A", "B"], "description": "..." }],
  "human_decisions_needed": ["..."],
  "final_pr_branch": "feature/xxx"
}
```

### 模式 3：模型路由适配

```markdown
## 角色
你是模型路由器。根据任务特征选择最合适的模型。

## 任务分析
{task_description}

## 路由规则
- complexity = low   → fast_model (GPT-5.6 Sol), max_tokens = 4096
- complexity = medium → balance_model, max_tokens = 8192
- complexity = high  → strong_model (GPT-5.5/Claude), max_tokens = 16384

## 任务类型加分
- 代码补全、简单 CRUD     → complexity 降 1 级
- 复杂重构、遗留代码解读   → complexity 升 1 级
- 涉及安全/支付/认证        → complexity 升 1 级，强制 strong_model

## 输出
{
  "assigned_model": "gpt-5.6-sol",
  "max_tokens": 4096,
  "reasoning": "简单 CRUD 任务，使用快速模型降低延迟和成本"
}
```

### 模式 4：检索上下文拼接

```markdown
## 角色
你是上下文组装器。将检索到的知识原子组装为 Agent 可用的精准背景信息。

## 检索结果
{retrieved_atoms_json}

## 组装规则
1. 按 ref_type 排序：depends > extends > references > config
2. depends 类型的引用全文注入，标记 [核心背景]
3. references 类型的引用提取关键段落，标记 [相关参考]
4. config 类型的引用只注入具体数值/参数，标记 [配置参数]
5. 超过上下文预算时，从 ref_type 优先级最低的开始裁剪

## 输出
直接输出拼接后的文本，每段标注原子来源：
[核心背景 | 来源: SQLite表结构设计]
DDL 内容...

[配置参数 | 来源: 渐进式检索引擎]
上下文窗口阈值: 70%
```

## Token 预算分配

| 上下文组成 | 占比 | 说明 |
|-----------|------|------|
| System Prompt（角色 + 规则） | 15% | 固定开销 |
| 核心背景（depends） | 25% | 必须理解的前置知识 |
| 相关参考（references） | 20% | 辅助理解 |
| 任务描述 + 验收标准 | 15% | 当前任务 |
| 配置参数 | 5% | 具体数值约束 |
| 对话缓冲 | 20% | 留白给 Agent 思考和输出 |
