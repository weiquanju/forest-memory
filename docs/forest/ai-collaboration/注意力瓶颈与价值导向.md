# 注意力瓶颈与价值导向

## 瓶颈的三次迁移

OpenClaw 创始人 Peter Steinberger 亲历瓶颈演变：

```
Token 数量（去年）
    ↓
计算资源
    ↓
注意力（现在）  ← 终极瓶颈
```

注意力无法像 Token 或计算那样简单增加。因此，**最重要的能力是决定注意力投向哪里**。

## "价值 > Token"原则

OpenAI 明确战略：

- 内部追求的是**"价值最大化"**，而非"Token 最大化"
- 目标不是自动化或取代工程师，而是**尽可能放大工程师的能力**
- 让 AI 写 1 万行平庸代码是浪费，让 AI 解决 1 个棘手的业务逻辑漏洞才是价值

## 协作铁律

- 人类负责定义**验收标准（Acceptance Criteria）** 和**不可触碰的底线**（如数据隐私规范）
- AI 自主决定"怎么做"（调用哪些库、如何分层）
- 人类只审核"做没做成"（是否通过集成测试、是否符合架构蓝图）
- 把 AI 当成能独立出结果的产出单元，而非执行指令的"高级复制粘贴"

## 模型迭代速度

| 指标 | 数据 |
|------|------|
| 发布周期 | 从每 15 个月缩短到每 6 周一个新版本 |
| GPT-5.6 Terra | 接近 GPT-5.5 的智能水平，但成本降低一半 |
| GPT-5.6 Sol (Cerebras) | 每秒 750 Token 推理，一份大规模 PR 约 10 秒完成 |

## 监督模式的转变

- **旧模式**：逐行 Code Review，盯着 Agent 输出代码
- **新模式**：静默跑批，异常唤醒

人类只设置"门禁（Gatekeepers）"：
- 编译报错
- 核心测试用例挂掉
- 引入高危开源协议

人类每天只需花 30 分钟进行**"策略性扫视"**——看 Agent 提交的 PR 摘要（变更了哪些模块、覆盖率变化），而非逐行看 diff。
