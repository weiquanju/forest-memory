# 协作反模式清单

## 反模式 1：微观管理（Micromanagement）

**症状**：逐行检查 AI 生成的代码，不断打断 Agent 执行流程，"这里用 for 循环不要用 map"。

**代价**：注意力浪费 + Agent 上下文频繁中断 + 人类沦为"高级语法检查器"。

**识别信号**：
- 你每天花 > 1 小时看 AI 写的代码 diff
- 你经常在 Agent 跑到一半时中断它
- 你给 Agent 的指令包含具体实现细节而非目标

**纠正方案**：
- 改用"异常唤醒"模式：只设置编译/测试/安全门禁
- 把审查粒度从"逐行"提升到"逐 PR 摘要"
- 给 Agent 完整的目标上下文后放手，让它跑完再评估

## 反模式 2：上下文溺亡（Context Drowning）

**症状**：在 System Prompt 中塞入全部领域文档，导致上下文窗口被静态信息占满，有效对话轮次急剧下降。

**代价**：Agent "看到太多、理解太少"，关键指令淹没在知识海洋中。

**识别信号**：
- System Prompt > 10,000 Token
- 每次对话 Agent 只响应前几轮的指令，后面的"遗忘"
- 你发现需要反复强调同一个约束

**纠正方案**：
- 使用元知识引擎的渐进式检索，按需注入精准背景
- System Prompt 仅保留 Agent 的角色定义、行为约束和检索指令
- 领域知识通过 `retrieve(query)` 动态拼接

## 反模式 3：盲目信任（Blind Trust）

**症状**：完全放权给 Agent，不设门禁，不审查 PR 摘要，直接 merge Agent 生成的代码。

**代价**：低质量代码积累 + 安全隐患 + 架构漂移。

**识别信号**：
- 你从不看 Agent 的 PR 摘要
- 测试覆盖率持续下降但你不知道
- Agent 引入了新的开源协议依赖你没有审查

**纠正方案**：
- 建立"策略检查点"：每天 30 分钟扫视 PR 摘要
- 设置自动门禁：编译、核心测试、开源协议检测
- 对关键模块（支付、认证、数据隐私）保留人工审查权

## 反模式 4：单模型绑定（Single Model Lock-in）

**症状**：所有任务都用同一个"最强模型"，不考虑成本、速度、任务匹配度。

**代价**：简单 CRUD 消耗高昂 Token 费用 + 慢速模型拖累交互体验。

**识别信号**：
- 你只有一个模型 API Key
- 你从不根据任务类型切换模型
- 完成简单代码补全也在等 10 秒以上

**纠正方案**：
- 建立模型路由层：简单任务 → 快模型（GPT-5.6 Sol），复杂任务 → 强模型（GPT-5.5/Claude）
- 按任务价值而非习惯分配模型资源

## 反模式 5：串行等待（Serial Waiting）

**症状**：给 Agent 一个任务后，干坐着等它完成，然后再给下一个任务。

**代价**：人类注意力碎片化 + Agent 串行执行的等待时间浪费。

**识别信号**：
- 你经常在 Agent 执行任务时刷手机
- 你每天实际专注工作时间 < 2 小时
- 你的 Manager Agent 每次只调度一个 Worker

**纠正方案**：
- 异步优先：一次发出多个子任务，让 Worker Agents 并行执行
- Manager Agent 汇总结果后统一上报
- 人类利用 Agent 执行时间做高价值决策（需求分析、架构评审）

## 反模式优先级矩阵

| 反模式 | 频率 | 代价 | 修复难度 | 优先级 |
|--------|------|------|---------|--------|
| 微观管理 | 极高 | 高 | 低 | 🔴 立即纠正 |
| 上下文溺亡 | 高 | 极高 | 中 | 🔴 立即纠正 |
| 盲目信任 | 中 | 极高 | 低 | 🟡 本周纠正 |
| 串行等待 | 高 | 中 | 低 | 🟡 本周纠正 |
| 单模型绑定 | 中 | 中 | 中 | 🟢 本月优化 |
