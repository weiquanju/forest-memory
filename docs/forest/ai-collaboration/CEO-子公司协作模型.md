# CEO-子公司协作模型

## 核心理念

未来人类与 AI 在软件工程领域的协作不是"人机结对编程"，而是**"人机组织协同"**——人类从"代码工匠"转型为"系统架构师 + AI 产品经理"的复合体。

## 组织类比

| 角色 | 对应 | 职责 |
|------|------|------|
| CEO | 人类工程师 | 设定方向、定义目标、做出关键决策 |
| CTO | Manager Agent | 任务拆解、Worker 调度、异常上报 |
| 开发小组 | Worker Agents | 具体执行：写代码、跑测试、Code Review |

## 实操流程

1. **人类发出需求** → 一句话定义业务目标和验收标准
2. **Manager Agent 拆解** → 自动将 Epic 拆分为子任务
3. **Worker Agent 执行** → 多 Agent 并行处理子任务
4. **自测与汇总** → Worker 跑完自测，Manager 汇总合并代码
5. **例外上报** → 只有遇到跨模块冲突或资源预算超标时，才上报人类

## 从"开十几个终端"到"管理一家 Agent 公司"

OpenClaw 创始人 Peter Steinberger 的亲历进化：
- **旧模式**：同时开十几个终端窗口，自己当调度器，不断切换上下文
- **新模式**：只和一个 Manager Agent 对话，由它分配任务给 Worker Agent
- **体验**："像在管理一家由多个 Agent 组成的小公司"

## Agent 循环的三个关键变化

1. **服务端上下文压缩**：让长期运行任务变得可靠，无需频繁重建会话
2. **协调机制**：一个线程即可创建、组织并管理多个项目和任务
3. **自动触发**：事件发生时系统能自动唤醒 Manager Agent

## 理想终态

Manager Agent 自动唤醒 → 创建 Worker → 完成代码修改 → 运行测试 → Code Review → 仅在需要人工决策时才上报

## 核心能力转移

人类工程师的"新三样"：

1. **上下文的质量**：给 Agent 输入的背景信息越精准，产出越好（注意力投喂）
2. **失败的容忍度**：允许 Agent 在沙盒里试错多少次，而不中途打断（信任边界）
3. **价值的判断力**：在 Agent 给出的 3 套方案中，凭业务直觉选出最符合产品生命周期的那个
