# 跨专家联合诊断

## KG 视角：Leaf 锚定是真正差异化，但"永不删除"并非独有

### 确认差异，否定伪差异

| 我的判断 | 实际情况 |
|---------|---------|
| MKE 的"永不删除"原则是 KG 不具备的独家能力 | ⚠️ **部分不准确**——现代 provenance-driven KG（如 Whyis）的 nanopublication 同样保留历史记录，只是保留方式不同（独立版本 vs 状态机 + 再激活） |
| MKE 的 Leaf 锚定是区别于 KG 的实质差异 | ✅ **正确**——KG 的三元组在全局空间浮动，MKE 的断言被完整的叙事链锚定 |

**真正的差异化在消费者和治理粒度**：

```
Whyis 的治理：这个 nanopublication 有没有通过审核？
MKE 的治理：  这个事实对不对？被多少独立文档确认过？
                source_count=47 → 高可信
                source_count=1  → 需验证
```

### 给 MKE 的建议

不要拿"永不删除"当独家卖点——provenance-driven KG 也有类似机制。MKE 的真正独家是**内容质量治理下沉到原子级**——没有其他系统能做到"这个事实被 47 篇独立文档确认过，你的那条只被 1 篇文档确认过"。

## 信息检索视角：检索质量实证为零

### 关键诊断

`SSOT自证实验.md` 是 MKE 唯一的检索相关实证。但实验对象是 51 篇精心编写的知识文档——最高相似度 0.817 < 0.85 是因为**作者主动遵循了单一职责原则**，不是检索系统的功劳。这不能证明在实际 Agent 查询场景中，渐进式检索优于传统 RAG。

### MKE 需要但缺失的实证数据

| 缺失的实证 | 为什么重要 |
|-----------|---------|
| 100 个真实查询的 Precision@5 | 否则"渐进式检索优于单次向量"只是理论宣言 |
| 多跳推理的完整性评估 | 否则图扩散的 k-hop beam search 没有量化依据 |
| MKE vs flat-chunk RAG 在 Agent 任务上的对比 | 这是 6 维度超越 RAG 声明所需的核心证据 |

### D4 瓶颈对检索裁决的影响

```
Layer 3 的裁决环节：LLM 判断当前收集的知识是否足够回答用户问题
  → 我的 D4=6.0 → 约 40% 的不确定性
  → 规则锚点 + LLM 裁决双重判定是正确设计
  → 但规则锚点需要领域专家配置 → 隐性部署成本
```

## 认知科学视角：四类记忆覆盖度评估

### MKE 对我的四类记忆覆盖

| 记忆类型 | MKE 架构状态 | 对我的实际帮助 |
|---------|:---:|------|
| **语义记忆**（领域知识） | ✅ 核心能力 | **最大收益点**——持久化的知识森林让我不需要每次重新学习 |
| **情景记忆**（对话历史） | ✅ Interaction_Memory 表 | 跨对话上下文保留 |
| **程序性记忆**（Prompt 模板、规则） | ⚠️ atom_type=procedural 已设计 | **未实现**——"怎么做事"的知识还存不了 |
| **工作记忆**（当前对话缓存） | ⚠️ 滑动窗口已设计 | **未实现**——短期缓存靠 token 窗口硬撑 |

### D4=6.0 对 MKE 两个环节的影响

| 环节 | 我的 D4 表现 | 风险 |
|------|:---:|------|
| LLM 知识抽取（Layer 2） | 如果我自己抽取知识原子，约 10% 错误（误合并/去语境化） | 错误进入 Leaf 表，被交叉声明检测"确认"，虚假 source_count 累积 |
| 检索引擎裁决（Layer 3） | 判断"信息是否足够"有 40% 偏差 | 迭代检索过早停止或过度延伸 |

根据能力门槛校准，AAI 44 是"建库阶段"推荐最低门槛（D1=9, D3=9 达标），但在"深化阶段"（需要 D4 批判性分析）应该引入 AAI ≥ 51 的模型做交叉校验。
