# 查询的旅程：从文本到 Token

## 你按下发送键的那一刻

你的句子不是以"完整语句"的形式进入 LLM 内部的。它先经过**分词器（Tokenizer）**——一个独立于 LLM 推理引擎的小工具。

```
输入："MKE 核心其实是在解决人类和 LLM 之间可持续对话的问题"
         ↓ 分词器
Token：["M", "KE", "核心", "其实", "是", "在", "解决", "人类", "和", "LL", "M", "之间", "可", "持续", "对话", "的", "问题"]
```

## 分词不是理解

分词是纯机械操作，基于预训练的 BPE (Byte Pair Encoding) 算法：

- 统计高频出现的字符组合，形成"子词"词典
- 从词典中匹配最长子词，逐段切割
- 不涉及任何语义理解

**关键特性**：
- 一个中文字通常 1-2 token；一个英文单词通常 1-3 token
- "LLM"被切成 ["LL", "M"]——因为分词器把大写字母序列拆开了
- 同一语义的不同语言表述，token 数可能差异显著
- 分词的"质量"（token 边界是否合理）直接影响注意力计算的效果

## 然后被放入"纸带"

分词后，"MKE 核心其实是在解决人类和 LLM 之间可持续对话的问题"不再是 22 个字，而是 17 个 token 的序列。这个序列被追加到上下文窗口的最右端：

```
[System Prompt tokens]           ← 行为规则
[第 1 轮 我之前的回答 tokens]      ← 对话历史
[你的这句话的 17 个 token]         ← 最新
                   ↑ 总 token 数 ≤ 上下文窗口上限
```

到这一步，你的问题进入了 LLM 的"视野"——但这还只是物理上的进入，就像纸条放到了桌子上。真正的"看一眼、读懂、判断"是注意力漫游的事。
