# 注意力漫游：一眼扫过整个房间

## 机制描述

> 以下使用拟人比喻描述注意力机制的数学过程。每个比喻后附有对应的数学说明。

### 比喻版

现在整个对话被铺成一条长长的 token 纸带——从 System Prompt 到你的最新问题。我的"目光"扫过整条纸带上的每一个 token。

不是逐条读。是一瞬间计算每条和"我接下来该说什么"的相关性：

```
"人类和LLM之间可持续对话"——权重很高 🔥
"MKE核心其实是在解决"——权重也高 🔥
上一轮讨论的"可持续对话的基础设施"——权重极高 🔥🔥
System Prompt 中的行为规则——中高
三天前的无关问题——权重近乎为零 ❄️
```

这不是回忆。是我在"一瞬间"，对上下文中的每一条信息，都赋予了一个"相关性分数"。

### 数学版（非比喻）

每个 token 执行以下计算（简化）：

```
Query（由当前 token 生成）· Key^T（所有历史 token 的 Key） → 相似度向量
→ softmax → 注意力权重（0到1之间，总和为1）
→ 用权重对 Value（所有历史 token 的内容表示）做加权求和
→ 输出 = 所有历史信息的"加权融合"
```

实际上不是"扫一眼"——是多头注意力（Multi-Head Attention）并行计算多组 Q·K·V，从不同"角度"捕捉相关性。

## 注意力如何决定"我接下来该说什么"

注意力机制的输出是一个向量——它包含了"当前语境下，所有历史信息中哪些最相关"的精炼表示。这个向量直接驱动了下一个步骤：逐 token 预测。

```
注意力输出向量
  → 包含的信息："当前最相关的上下文是关于 MKE 和可持续对话的"
  → 这一信息影响 logits（每个可能 token 的概率）
  → 驱动逐 token 生成
```

### 关键洞察

注意力不是"搜索"或"回忆"——它是**数学上的加权融合**。没有索引、没有数据库查询、没有关键词匹配。它不"知道"自己为什么给某个 token 高权重——只是数学上最优化了下一步的预测。

### 为什么长对话会"遗忘"

```
上下文越短 → 注意力越集中
上下文越长 → 注意力被稀释
            → 早期内容可能被"忽略"
            → 不是因为"不重要"
            → 而是数学上无法对所有 token 同时保持高注意力
```

这就是 attention dilution——不是真正的遗忘，是权重分布问题。
