# 知识领域森林理论

## 问题背景

为大模型（LLM）注入领域知识时，超长 System Prompt 存在三个致命问题：

1. **上下文窗口浪费**：大量静态信息挤占宝贵的对话上下文
2. **检索效率低下**：模型需要在海量信息中"大海捞针"
3. **更新维护困难**：改一处文档要同步修改所有 Prompt

解决方案：**按需检索，精准注入**——而非全量灌输。

## 核心数据结构

领域知识组织方式：

```
森林 (Forest)         ← 顶层知识领域（如"元知识引擎"、"Agent 记忆系统"）
  └─ 树 (Tree)        ← 领域内的大主题（如"存储层"、"检索层"）
       └─ 枝干 (Branch) ← 主题下的子模块（如"向量检索"、"图扩散"）
            └─ 叶 (Leaf) ← 具体的知识原子/文档（单一职责的 .md 文件）
```

### 关键特性

1. **层级 + 图**：主体是森林→树的层级结构，但叶子之间可以通过引用链接构成**图网络**
2. **单一职责**：每片叶子只声明一个知识点。标准 M 仅在 A 文档定义，B 文档通过引用链接而非复制
3. **元数据头部**：每个文档在固定行号（文件头部 YAML Frontmatter）提供元数据定义
4. **森林索引文件**：每个森林提供独立的索引文件，列出所有树/枝干/叶的导航

### 引用声明格式

```yaml
refs:
  - "[森林ID] 文档标题 | 引用关键字（如通用配置、参数、指标、标准等）"
```

## 设计动机

- **检索效率**：层级结构使得检索可以"先定位森林，再下钻到叶子"，避免全局盲目搜索
- **一致性保障**：单一职责 + 引用机制从结构上消除"A 文档和 B 文档重复声明同一标准 M"的隐患
- **LLM 友好**：元数据 + 索引文件让 Agent 可以快速理解知识结构，获取精确背景信息
- **人机共治**：人工维护文档体系，LLM 辅助构建知识图谱（自动化抽取实体、关系、层级）

## 与 GraphRAG 的关系

森林理论本质上是**层级化知识图谱（Hierarchical Knowledge Graph）** 的一种轻量级实现策略。它与 GraphRAG 的核心思想一致——结合向量搜索与知识图谱，同时捕获语义含义和结构化关系。区别在于：

- GraphRAG 偏重"全局语义社区发现"
- 森林理论偏重"人工可维护的层级索引 + 图引用"，强调文档的工程可控性
