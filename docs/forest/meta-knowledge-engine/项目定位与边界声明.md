# 项目定位与边界声明

## 最终定位

**MKE = AI 知识质量基础设施（AI Knowledge Quality Infrastructure）**

不局限于 RAG 场景，而是面向所有需要"知识组织 + 质量治理 + 精准检索"的 AI 应用场景。RAG 只是 MKE 的消费场景之一，Agent Memory、训练数据治理、知识库迁移等同样是 MKE 的消费场景。

原"RAG 知识治理引擎"定位不准确——RAG 只是 MKE 第三层（检索引擎）的一个简化子集。

## 六维度超越传统 RAG

MKE 架构在 6 个维度上超越传统 RAG：

| 维度 | 传统 RAG | MKE |
|------|---------|-----|
| 知识组织 | 扁平 chunk | 层级图（Forest→Tree→Branch→Leaf） |
| 检索策略 | 单次向量 | 五阶段渐进（粗筛→图扩散→裁决→迭代→防溢出） |
| 知识治理 | 零治理 | SSOT + 三层冲突检测 |
| 记忆融合 | 无状态 | 四类记忆 + 巩固管道 |
| 知识原子化 | 机械切割 | 语义切割（单一职责） |
| 可追溯性 | 无溯源 | 有溯源（refs 引用链 + 版本快照） |

## 边界声明（"MKE 不做什么"）

以下边界声明用于逐项校验每一条架构设计和知识注入是否越界：

| MKE 做（核心能力） | MKE 不做（留给其他系统） |
|---|---|
| 精炼知识的**组织**（层级、分类、atom_type） | **ETL/数据管道**——大规模文档清洗、格式转换归 Spark/Ray |
| 知识**质量校验**（交叉声明、一致性、冲突检测） | **大规模去重**——MinHash/LSH 级去重归专门工具 |
| 知识**版本回溯**（快照、状态机、永不删除） | **格式转换**——.pdf→.md 等归文档解析工具 |
| 知识**一致性追踪**（级联检测、引用链路） | **向量数据库**——MKE 用 sqlite-vec 做轻量嵌入，不替代 Milvus/ChromaDB |
| 知识**检索质量保障**（规则锚点、防校准退化、可追溯） | **Agent 行为管理**——Worker 调度、任务拆解、对话管理归 LangChain/Dify |
| 知识**生命周期管理**（衰减、淘汰、再激活） | **全文搜索引擎**——FTS5 仅做关键词辅助，不替代 Elasticsearch |
| 作为**知识质量治理层**被 RAG/Agent 框架消费 | **成为 RAG/Agent 框架本身**——不替代 Dify/LangChain/LlamaIndex |

**每一条架构细化建议必须在上述边界内——如果一项建议在边界上模糊，应明确收紧其职责范围。**

## 品类定位

MKE 瞄准的是**知识内容存量质量**的治理，治理粒度是**知识原子级**——这是当前所有 Agent Memory 框架、RAG 工具和幻觉检测系统都未覆盖的层级。

| 项目 | 治理对象 | 治理粒度 | 与 MKE 重叠度 |
|------|---------|---------|:---:|
| PKA | Agent **工作流质量** | 任务级 | 0% |
| Khala | 系统**架构一致性** | 系统组件级 | < 10% |
| MKE | **知识内容存量质量** | **知识原子级** | — |

三个项目治理三个完全不同的层级。PKA 和 Khala 的存在不是竞争威胁，而是间接验证了"质量治理"作为方向的正确性。

## 时间窗口

MKE 有一个 **12-18 个月的窗口期**：在大模型能力足够便宜且可靠、但知识治理品类尚未被大厂垄断的时间窗口内，先行建立品类认知和技术壁垒。

Agent Memory 赛道 2025-2026 年爆发式增长（腾讯、Redis、Neo4j、字节跳动全线入局），但所有产品聚焦"存+检索"能力，预计 2026-2027 年会从"怎么记住"自然过渡到"记住的对不对"——这是 MKE 的最佳切入时机。
