# 单一职责与引用机制

## 问题：知识冗余与一致性危机

典型场景：
- A 文档声明标准 M
- B 文档又声明一次同样的标准 M
- 导致多处维护、漏改——**知识冗余（Knowledge Redundancy）** 和**一致性危机（Consistency Crisis）**

## 解决方案

### 1. 单一职责（Single Responsibility）

每个知识点（文档）只有**一处权威来源（Single Source of Truth, SSOT）**。

- 标准 M 只在 A 文档中定义
- B 文档通过引用（Reference）而非复制（Copy）来使用

### 2. 引用而非复制

在文档 YAML 头部通过 `refs` 字段声明引用：

```yaml
refs:
  - "[mke] 知识领域森林理论 | 通用配置：文档组织原则"
  - "[aic] 注意力瓶颈与价值导向 | 参数：上下文窗口阈值 70%"
```

引用声明包含三个要素：
- **森林 ID**：`[mke]`、`[aic]` 等
- **文档标题**：被引用文档的标题
- **引用关键字**：说明引用的具体内容（通用配置、参数、指标、标准等）

### 3. 元数据头部定义

每个文档在**固定行号（文件头部）** 提供 YAML Frontmatter：

```yaml
---
forest: mke                    # 所属森林 ID（必填）
tree: 基础理论               # 所属树（必填）
branch: 知识治理               # 所属枝干（必填）
title: 单一职责与引用机制       # 文档标题（必填）
version: 1.0.0                 # 语义版本号（必填）
created: 2026-07-12            # 创建日期（必填）
updated: 2026-07-12            # 最后更新日期（必填）
description: ...               # 文档描述（必填）
keywords:                      # 检索关键字（可选）
  - 单一职责
  - 引用去重
refs:                          # 引用声明（可选）
  - "[森林ID] 文档标题 | 引用关键字"
---
```

## 构建时的强制执行

在知识图谱构建（第二层）时：

1. LLM 抽取知识原子时，自动检测是否与已有 Leaf 节点的内容重复
2. 若发现 B 文档重复声明了 A 文档的标准 M → **自动拒绝写入**
3. 返回提示："请引用 A 文档的 Leaf_ID：xxx，而非重复声明"
4. 将交叉声明消灭在**构建环节**，而非事后排查

## 检索时的引用追溯

- References 表存储 `from_leaf_id → to_leaf_id` 的引用边
- 检索时通过 1-hop 扩散，自动将被引用的"标准定义"一并拉取
- 确保 Agent 获得的上下文既完整又精炼，不重复
