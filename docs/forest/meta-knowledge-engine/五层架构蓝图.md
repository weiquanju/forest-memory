# 五层架构蓝图

## 设计理念

元知识引擎必须具备**普适性**——既能服务于代码工程（Spring Boot 源码），也能服务于商业策划（Q4 营销案）。靠的是**数据结构的一致性**，而非"插件适配的复杂性"。

## 架构总览

```
┌─────────────────────────────────────────────────────────┐
│  第五层：治理与校验层                                       │
│  版本快照 / 死链检测 / 一致性校验 / 文档生命周期管理          │
├─────────────────────────────────────────────────────────┤
│  第四层：持久化与记忆融合层                                  │
│  Interaction_Memory / 个性化 PageRank / 经验回灌           │
├─────────────────────────────────────────────────────────┤
│  第三层：混合检索引擎层                                     │
│  向量粗筛 → 图扩散 → 裁决迭代 → 窗口防溢出                   │
├─────────────────────────────────────────────────────────┤
│  第二层：知识构建与图索引层                                  │
│  层级存储 (Forest/Tree/Branch/Leaf) + 引用图谱 + 向量嵌入    │
├─────────────────────────────────────────────────────────┤
│  第一层：数据接入与归一化层                                  │
│  知识原子（Knowledge Atom）+ 统一元数据头 + 同步触发           │
└─────────────────────────────────────────────────────────┘
```

## 第一层：数据接入与归一化层

**核心任务**：将所有输入源统一转化为"知识原子（Knowledge Atom）"

### 代码域
- 利用 OpenCode/Codex 扫描 AST（抽象语法树）
- 提取：函数签名、类依赖、配置项注解
- 自动生成带注解的"文档快照"，不入侵业务代码

### 商业域（如策划案）
- 直接消费 Markdown/Word
- 通过 LLM 提取：目标、关键指标（KPI）、资源依赖、时间节点

### 统一口径
每个知识原子必须包含 **YAML Frontmatter 元数据头**：
- `forest`：所属森林 ID
- `tree` / `branch`：所属树和枝干
- `version`：版本号
- `tags`：领域标签（如 `backend/config` 或 `marketing/campaign`）

### 同步触发
- 代码域：Git Hook（CI/CD 触发扫描）
- 商业域：文件系统监听（或手动触发重算）
- 两者逻辑完全一致，仅输入源不同

## 第二层：知识构建与图索引层

**核心任务**：将知识原子组装为森林→树→枝干→叶的层级，构建带权重的引用图

### 层级存储（SQLite 关系表）
- `Forest` 表：项目/业务线
- `Tree` 表：模块
- `Branch` 表：子模块
- `Leaf` 表：具体文档/函数/参数
  - 必须存储 `Content_Path`（原始文件路径）和 `Content_Hash`（变更检测）

### 引用图谱（邻接表）
- `References` 表：`from_leaf_id`, `to_leaf_id`, `ref_type`（调用、继承、依赖、引用依据）
- **单一职责强制执行**：LLM 抽取时若发现 B 文档重复声明了 A 文档的标准 M，引擎自动拒绝写入，提示"请引用 A 文档的 Leaf_ID"

### 向量嵌入
- 使用 sqlite-vec 扩展
- 每个 Leaf 节点正文生成 768/1536 维向量
- 与关系表通过 `Leaf_ID` 一一对应

## 第四层：持久化与记忆融合层

参见 [Agent Memory 能力对齐](Agent-Memory能力对齐.md)

### 核心机制
- `Interaction_Memory` 表：Session_ID、Query、Retrieved_Leaf_IDS、Final_Answer、User_Correction
- **记忆回灌**：高频引用且未被修正的叶子自动提升权重（个性化 PageRank）
- **经验覆盖**：用户修正过的答案优先级高于原始文档

## 第五层：治理与校验层

### 版本快照
- 每次构建知识图谱记录全局 `Epoch_ID`
- Leaf 更新时旧版本保留 3 个迭代回退

### 死链检测
- 每日定时任务扫描 `References` 表
- 发现 `to_leaf_id` 失效则生成废弃报告

### 一致性校验
- 代码变更时自动检测相关文档是否需要更新（CI/CD 嵌入）
- Docstring/注解中嵌入文档引用，形成"代码→文档"双向链接

## MVP 实现建议（个人使用）

- **数据库**：单文件 SQLite（`domain_knowledge.db`），内含 5 张核心表
- **依赖库**：sqlite-vec（向量）+ openai/anthropic（抽取）+ tree-sitter（代码 AST）+ markdown-it（文档解析）
- **构建脚本**：`build_knowledge.py`，递归扫描 `.md` / `.py` / `.java` 文件
- **检索接口**：`retrieve(query)` 函数，实现三段式检索，输出 Context String 拼接至 Agent Prompt
