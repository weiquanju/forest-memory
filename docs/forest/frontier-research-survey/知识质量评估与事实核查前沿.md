# 知识质量评估与事实核查前沿

## 核心问题

知识质量评估是确保 LLM 输出可靠性的关键环节。目标：让每条推理结论可被验证、每项知识来源可被追溯。

## 一、KG 增强事实核查

### KG-CRAFT [20]

KG 增强自动事实核查：

- 从声明和报告中构建 KG
- 基于 KG 结构制定**上下文相关的对比性问题**引导证据提炼
- LIAR-RAW 和 RAWFC 真实世界数据集 SOTA

### GraphCheck [21]

GNN 将 KG 处理为**软提示（soft prompt）**，LLM 单次推理完成精确高效的事实核查：

- 捕获多跳推理链（现有方法常忽略）
- 7 个基准整体提升最高 **7.1%**
- 医学等专业领域超越专用事实核查器

### 其他方法

| 方法 | 机制 | 亮点 |
|------|------|------|
| CommunityKG-RAG [22] | KG 社区结构集成到 RAG | 无需额外训练跨领域适配 |
| HybridFC [23] | 集成文本/路径/规则/嵌入四种方法 | FactBench AUC +0.14-0.27 |
| Hybrid Pipeline [28] | KG+LLM+Web Agent 模块化管道 | FEVER F1=**0.93**，KG 不足时自动回退 Web |
| Semantic Triples [29] | 声明→语义三元组+KG 增强 | 零样本超越先前方法 |
| WKGFC [30] | 多源多 Agent+MDP 证据检索 | KG + Web 协同证据检索 |

## 二、知识冲突检测

### 跨模态参数化知识冲突 [24]

大型视觉-语言模型中视觉和语言组件间存在持续高冲突率：
- 提出**动态对比解码**缓解冲突
- ViQuAE 和 InfoSeek 平均准确率提升 **2.24%**

### ConflictBank 基准 [25]

首个系统评估 LLM 知识冲突的基准（NeurIPS 2024），覆盖三类冲突：

1. **上下文-记忆冲突**：当前对话与模型参数知识矛盾
2. **上下文间冲突**：不同输入片段相互矛盾
3. **记忆内冲突**：模型内部知识自相矛盾

**核心发现**：LLM 面对知识冲突行为高度复杂，取决于冲突类型、领域和模型能力。

## 三、知识可追溯性

### ToG 的可追溯证明 [3]

推理路径每一步可回溯到 KG 具体事实三元组，人类专家可检查并纠正错误推理——"人在回路中"提升透明度和可信度。

### RL 可解释事实核查 [27]

RL Agent 计算证明/反驳事实声明的路径，路径可呈现给人类读者自行判断证据说服力——人机协同可解释范式。

### 统一事实一致性评估 [26]

Agarwal 统一了 NLI、摘要评估、事实性验证和事实一致性评估四项任务，模型在 22 个数据集综合基准上 SOTA，实现跨域泛化。

## 四、方法对比

| 方法 | 核心机制 | 需 KG | 证据来源 | 可解释性 | 最佳表现 |
|------|---------|:---:|------|:---:|------|
| KG-CRAFT [20] | 对比性问题生成 | 是 | KG+文本 | 中 | SOTA on LIAR-RAW |
| GraphCheck [21] | GNN 软提示+多跳推理 | 是 | KG 嵌入 | 低（GNN 黑箱） | 7 基准 +7.1% |
| Hybrid Pipeline [28] | KG+LLM+Web 回退 | 首选 | KG+Web | **高** | FEVER F1=0.93 |
| RL-based [27] | RL Agent 计算路径 | 是 | KG 路径 | **高**（可呈现给人） | — |

## 五、开放挑战

- FEVER F1=0.93 但跨领域泛化（Climate-FEVER）下降至 0.78-0.85
- 三类知识冲突（上下文-记忆/上下文间/记忆内）尚无统一缓解策略
- 人在回路验证成本的降低路径："每条路径审核"→"异常检测+抽样审核"
