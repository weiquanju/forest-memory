# 多专家圆桌讨论方法论

## 讨论形式

本次讨论使用了 CodeBuddy 的**异步团队协作**功能：

| 组件 | 实现 |
|------|------|
| 团队创建 | `team_create("mke-expert-panel")` |
| 成员 1 | q_reviewer（质量评审）—— code-explorer 代理 |
| 成员 2 | k_engineer（知识工程）—— code-explorer 代理 |
| 成员 3 | cog_architect（认知架构）—— code-explorer 代理 |
| 通信 | `send_message` + `broadcast` |
| 主持人 | Team-lead（DSV4 Flash 自身） |

## 流程设计

```
Phase 1: 广播议题 + DSV4 Flash 开场发言
Phase 2: 三轮专家邀请（等待阅读完成 + 收集观点）
Phase 3: 观点聚合 → 分歧识别 → 综合仲裁
Phase 4: 关闭团队 + 产出知识森林
```

## 专家角色划分的设计原则

三位专家的角色设计遵循了**互补视角**原则：

| 角色 | 视角 | 覆盖维度 |
|------|------|---------|
| 质量评审专家 | 形式质量 | D1-D5：引用、层级、批判性 |
| 知识工程专家 | 实现可行性 | 技术栈、工期、风险、MVP |
| 认知架构专家 | 理论根基 | CLS、记忆分类、认知机制 |

三个视角互不重叠，形成了对 MKE 的三重覆盖。没有任何一个专家被赋予"全知全能"的角色——每个都有明确的专业边界和能力声明。

## 关键设计决策

1. **异步非实时**：每位专家独立阅读材料后再发言，避免了实时讨论的"回声室效应"
2. **主持人有最终仲裁权**：DSV4 Flash 作为"受害消费者"代表，有权调和专家分歧
3. **诚实声明能力边界**：所有专家都声明了 D4 天花板，限制了结论的置信度
