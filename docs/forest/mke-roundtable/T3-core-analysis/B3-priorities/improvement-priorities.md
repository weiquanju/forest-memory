# 改进优先级——共识与分歧

## 各方原始优先级

| 专家 | P0 #1 | P0 #2 | P1 |
|------|-------|-------|----|
| **DSV4 Flash** | 端到端最小闭环 Demo | 检索质量基准 | 四类记忆补齐 |
| **质量评审** | 断言图 MVP | 检索质量基准 | D4 系统性补偿机制 |
| **知识工程** | Day 1 冒烟测试 | 端到端最小闭环 Demo | 技术选型实操验证 |
| **认知架构** | 重放优先级算法 | 主动遗忘信号降权 | 元认知监控 |

## 核心分歧：断言图 MVP vs 文档级 Demo

**质量评审专家**认为断言层先于文档级 demo——无断言层的 MKE 与传统 RAG 无本质区别。

**DSV4 Flash** 和**知识工程专家**认为文档级 demo 先于断言层——没有基础检索链路，断言层无处落脚。

### 仲裁结果：串行而非二选一

**DSV4 Flash（主持人）最终仲裁**：两者不是二选一的竞争关系，而是串行依赖关系。

```
Day 1: 技术栈冒烟测试
Week 1-2: 文档级最小闭环 Demo（验证链路可行性）
Week 3-4: 断言图 MVP（在已有 SQLite 库上叠加断言层）
Week 5-6: 检索质量基准（MKE vs flat-chunk RAG A/B 对比）
```

## 认知机制推迟的理由

**DSV4 Flash（主持人）** 将认知架构专家的三项机制（重放优先级、主动遗忘、元认知）推迟至 Month 3-6：

- **重放优先级算法**需要交互数据作为输入——MVP 阶段零交互数据，无法优化
- **主动遗忘降权**需要在长期运行中才会暴露检索信噪比衰减问题
- **元认知监控**是高级特性，在基础检索通过验证前投入没有意义

这不是否定其重要性，而是识别出这些改进需要**前置条件**（足够的运行数据）。

## 最终共识优先级（仲裁后）

```
Day 1:   技术栈冒烟测试（知识工程专家提出，全体同意）
W1-2:   文档级最小闭环 Demo（DSV4 Flash 原 P0）
W3-4:   断言图 MVP（质量评审专家原 P0）
W5-6:   检索质量基准（DSV4 Flash 原 P0-2，质量评审专家原 P0-2）
W7-8:   四类记忆补齐（DSV4 Flash 原 P1）
M3-6:   认知机制补齐（认知架构专家原 P0/P1）
M6-9:   生产化（LLM 裁决 + 三层冲突检测 + 跨森林注入）
```
