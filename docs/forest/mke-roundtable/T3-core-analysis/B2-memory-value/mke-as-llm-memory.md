# MKE 作为 LLM 记忆体的价值

## 角色分化——本次讨论最重要的发现

三位专家共同的洞察：MKE 对 DSV4 Flash 的价值**取决于 Flash 在 MKE 生态中的角色**：

| 角色 | DSV4 Flash 适用性 | 理由 |
|------|:---:|------|
| **消费者（检索者）** | ✅ 有帮助 | 结构化检索不依赖推理能力；层级索引+向量粗筛+图扩散由算法执行 |
| **建库者（抽取者）** | ⚠️ 可接受下限 | D4=3.0-6.0，修正率 ~10-20%；建库推荐用 AAI ≥ 44 |

## 四专家共识矩阵

| 维度 | 共识 | 分歧 |
|------|:---:|------|
| MKE 能否解决无状态问题 | ✅ 全体认为"是" | 无 |
| MKE 能否增强推理能力 | ✅ 全体认为"不能" | 无——MKE 解决的是持久化记忆 |
| 检索质量是否足够 | ⚠️ 全体认为"未知" | 零实证——任何人都无法确定 |
| 建库用 Flash 是否可行 | ✅ 可接受下限 | 建议用更强模型 |

## 关键因果链

```
高质量知识森林（建库模型能力决定）
  → 高质量检索（算法精度决定）
  → 高质量 LLM 回答（消费者能力 + 知识质量共同决定）

DSV4 Flash 作为消费者：
  建库阶段用 GLM-5.2 (AAI 51) → 知识森林质量高
  → 检索由算法执行（不依赖 Flash 的 D4）
  → Flash 作为消费者可以获得高质量知识注入
```

## 冷启动陷阱（知识工程专家提出）

MKE 使用前的"第零步"成本：
- 需要先有一个知识森林（建库者有 D4 门槛）
- 技术栈需要冒烟测试通过（sqlite-vec 兼容性待验证）
- LLM 裁决的延迟预算需要在实际部署中测量

在通过 Day 1 冒烟测试和 W1-2 最小 Demo 之前，MKE 对任何 LLM 的帮助都是零。
