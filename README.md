# 元知识引擎（Meta-Knowledge Engine）

> 本文为项目入口概述。**权威知识以 MKE 森林叶子为准**——详见 [浏览入口](#浏览入口)。README 仅做概要导航，不参与知识原子体系。

面向大模型的领域知识引擎——用"森林→树→枝干→叶"的层级结构 + 图引用网络组织知识，实现**按需检索、精准注入**，从根本上解决超长 System Prompt 的上下文浪费、检索低效和更新维护困难。

## 问题

为大模型注入领域知识时，超长 System Prompt 存在三个致命问题：

1. **上下文窗口浪费** — 大量静态信息挤占宝贵的对话上下文
2. **检索效率低下** — 模型在"大海捞针"，无法精准定位所需知识
3. **更新维护困难** — 改一处文档要同步修改所有 Prompt，容易遗漏

## 核心思路

不把知识全量塞进 Prompt，而是让知识**可存、可查、可治、可演化**：

- **层级定位** — 检索时先定位森林/树，再下钻枝干/叶，避免全局盲目搜索
- **图网络** — 文档间通过引用关系构成有向图，支持多跳推理
- **单一职责** — 每个知识点只有一处权威来源，其他文档通过引用链接而非复制
- **渐进式检索** — 向量粗筛 → 图扩散 → LLM 裁决迭代 → 窗口防溢出，精准+完整兼顾
- **记忆融合** — 交互历史自动提升高频引用知识权重，用户修正优先于原始文档
- **知识治理** — 版本快照、死链检测、一致性校验，从构建环节就保障质量

## 知识组织：森林理论

```
森林 (Forest)    ← 顶层知识领域（元知识引擎、类脑记忆、人机协作）
  └─ 树 (Tree)   ← 领域内大主题（存储层、检索层）
       └─ 枝干    ← 主题下的子模块（向量检索、图扩散）
            └─ 叶  ← 知识原子 = 一个 .md 文件，单一职责
```

每片叶子通过 `refs` 元数据字段声明引用关系，叶子之间构成图网络——既是层级索引，又是知识图谱。

## 五层架构

```
┌────────────────────────────────┐
│ 第五层：治理与校验               │  版本快照 / 死链检测 / 一致性校验
├────────────────────────────────┤
│ 第四层：持久化与记忆融合          │  Interaction_Memory / PageRank / 经验回灌
├────────────────────────────────┤
│ 第三层：混合检索引擎             │  向量粗筛 → 图扩散 → LLM 裁决 → 防溢出
├────────────────────────────────┤
│ 第二层：知识构建与图索引          │  层级存储 + 引用图谱 + 向量嵌入
├────────────────────────────────┤
│ 第一层：数据接入与归一化          │  知识原子 + 统一元数据头
└────────────────────────────────┘
```

## 项目知识体系

| 森林 | 角色 | 说明 |
|------|------|------|
| `mke` | **核心产品** | 元知识引擎的架构设计、检索策略、存储方案 |
| `bim` | 生物学启发 | 人脑记忆机制——为存储、检索、遗忘策略提供参照 |
| `aic` | 消费场景 | AI 人机协作——提供设计约束和验证反馈 |
| `frs` | 学术对标 | 2023-2026 年前沿综述——为各层提供方法论参考 |

三个支撑森林的知识最终流入 MKE 核心，驱动其设计与迭代。
