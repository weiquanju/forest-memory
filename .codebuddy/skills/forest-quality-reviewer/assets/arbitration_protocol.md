# 交叉评审仲裁协议

> 当交叉评审中评审者间出现评分分歧时，按本协议执行仲裁。
> 本协议基于 exp-model-20260716-01 实验实证设计，适配 CodeBuddy CN 可用模型约束。

---

## 1. 触发条件

### 三级触发

| 级别 | 条件 | 处理方式 |
|------|------|---------|
| **硬触发** | 任何维度差 ≥2 分 | 必须仲裁 |
| **软触发** | 主观维度（D4/D5）差 =1 分 + 评审者 AAI 差 ≥7 | 建议仲裁 |
| **不触发** | 客观维度（D1/D3）差 ≤1 分 或 AAI 差 <7 | 取均值，标注置信度 |

> exp-model-20260716-01 中 D2(8vs9)/D4(8vs7)/D5(8vs9) 均为差 1 分。D4 因 AAI 差 11（40 vs 51）触发软触发。

---

## 2. 仲裁者选择（CodeBuddy CN 约束）

### 2.1 可用模型 AAI 全景

| 模型 | AAI | 家族 | 仲裁适用性 |
|------|:---:|------|---------|
| GLM-5.2 | 51 | Zhipu | 被评审者 AAI ≤44 时可用 |
| **MiniMax-M3** | **44** | **MiniMax** | **推荐仲裁者**（不同家族，$0.22） |
| Kimi-K2.6 | 44 | Moonshot | 备选仲裁者 |
| Kimi-K2.7-Code | 42 | Moonshot | 被评审者 AAI ≤40 时可用 |
| Hy3 | 41 | Tencent | 被评审者 AAI ≤40 时可用 |

> GLM-5.2 (AAI 51) 是 CodeBuddy CN 中最高的。没有 AAI >55 的模型。

### 2.2 选择策略

#### 被评审者 AAI ≤44

优先使用非实验参与者的其他 CodeBuddy CN 模型：

- **推荐**: MiniMax-M3 (AAI 44, $0.22) — 不同家族，价格最低，中立角色
- 备选: Kimi-K2.6 (AAI 44, $0.70)
- 仲裁者 AAI 必须 ≥ 被评审者 AAI
- 仲裁者不得与被评审者同模型家族（避免同族偏差）

> 当被评审者是 dsv4flash(40) 或 dsv4pro(44) 时，MiniMax-M3 是理想仲裁者——不同家族、AAI 持平或更高、价格最低。

#### 被评审者 AAI =51

使用规则仲裁（P3）：

- 仲裁者不依赖模型，基于 skill 标准判定
- 仲裁方式：根因分析 → skill 标准核对 → 判定均值是否可接受
- 同模型自仲裁（P4）作为兜底，限制为根因分析，不做独立打分

> 当被评审者是 glm52(51) 时，无 AAI >51 的可用模型。规则仲裁是唯一可行方案——实验证明此方式有效。

#### 未来扩展

当 CodeBuddy CN 增加 AAI >55 的模型（如 Claude Sonnet 4.6）时，恢复 P1 级第四方仲裁者。

### 2.3 仲裁者偏差风险矩阵

| 仲裁者类型 | 偏差风险 | 缓解措施 |
|------------|:---:|---------|
| 非实验参与者（MiniMax-M3 等） | 低 | 不同家族，无自利偏差 |
| 评审者中 AAI 更高者 | 中 | 可能同族偏差，声明风险 |
| 规则仲裁（不依赖模型） | 无 | 基于 skill 标准，但可能不够灵活 |
| 同模型自仲裁 | 高 | 限制为根因分析，不做独立打分 |

## 3. 仲裁流程

### 3.1 分歧检测

检测评审者间评分差异，按触发条件判定是否需要仲裁。

### 3.2 仲裁者选择

按 §2 策略选择仲裁者。

### 3.3 根因分析

逐维度分析分歧原因：

| 根因类型 | 识别方法 | 处理方式 |
|---------|---------|---------|
| **方法论分类差异** | 核对 skill 定义的维度边界 | 按 skill 标准判定哪个评审者正确 |
| **抽样代表性差异** | 对比评审者抽样分布（Tree 覆盖、叶数） | 要求补充抽样后重评 |
| **评分项自定义** | 核对评审者是否使用了 skill 未定义的评分项 | 按 skill 定义的评估项重新评分 |
| **纯主观判断差异** | 排除以上三种后仍存在分歧 | 仲裁者独立评分，取三者中位数 |

> exp-model-20260716-01 仲裁发现：3 个分歧点中 2 个（D2/D5）是方法论分类差异，1 个（D4）是抽样代表性差异。均为非能力偏差。

### 3.4 结果处理

| 情况 | 处理 |
|------|------|
| 均值可接受 | 维持均值，标注置信度和偏差方向 |
| 均值不可接受 | 采用更符合 skill 标准的评分 |
| 仍无法判定 | 引入更高优先级仲裁者（如有）；无可用模型时维持均值并标注"低置信度" |

### 3.5 仲裁置信度标注

| 置信度 | 条件 | 标注方式 |
|--------|------|---------|
| High | 无分歧或客观维度（D1/D3）一致 | 不需标注 |
| Medium | 主观维度差 =1，均值经根因分析确认可接受 | 标注偏差方向 |
| Low | 主观维度差 ≥2 或仲裁者偏差风险高 | 标注"低置信度，建议后续补充评审" |

## 4. 仲裁报告格式

### 4.1 Frontmatter

```yaml
---
arbitration_target: {被评审模型}
arbitration_dimensions: [有分歧的维度列表]
arbitrator: {仲裁者模型} (AAI {分数})
arbitration_date: {日期}
reviewer_a: {评审者A} (AAI {分数})
reviewer_b: {评审者B} (AAI {分数})
disagreement: "{维度}({评分A} vs {评分B}) 各差 {分差}"
arbitrator_bias_risk: {低/中/高}
arbitration_type: {P2-非实验参与者 / P3-规则仲裁 / P4-同模型自仲裁}
---
```

### 4.2 必填章节

1. **§1 分歧概览** — 维度/差值/均值
2. **§2 根因分析** — 逐维度分析分歧原因（按 §3.3 四类根因）
3. **§3 仲裁判定** — 根因定性 + 均值是否可接受 + 是否需要第三评审者
4. **§4 对 skill 的反馈建议** — 如有方法论改进建议（移交对应 P 任务）
5. **§5 最终评分确认** — 含置信度标注（High/Medium/Low）
6. **§6 仲裁者偏差声明** — 强制

### 4.3 偏差声明要求（强制）

每份仲裁报告必须在 §6 声明：

1. 仲裁者与被评审者是否同模型/同家族
2. 自利偏差风险评估（低/中/高）
3. 缓解措施（如不做独立打分、实证偏向更低分等）
4. 实证样本覆盖率（读了多少叶子）

## 5. 实验实证

### 5.1 exp-model-20260716-01 仲裁案例

| 项目 | 内容 |
|------|------|
| 仲裁目标 | glm52 (AAI 51) |
| 分歧维度 | D2(8vs9)、D4(8vs7)、D5(8vs9) |
| 仲裁者 | GLM-5.2 (AAI 51) — 同模型自仲裁（P4） |
| 仲裁方式 | 根因分析，不做独立打分 |

### 5.2 仲裁结论

| 维度 | 根因 | 均值 | 置信度 | 仲裁结论 |
|------|------|:---:|:---:|---------|
| D2 | 方法论分类差异（引用缺失误计入 D2） | 8.5 | Medium | 偏向 9（dsv4pro 符合 skill），均值保守可接受 |
| D4 | 抽样代表性差异（dsv4flash 偏向 T3 深叶子） | 7.5 | Medium | 偏向 7（dsv4pro 抽样更 representative），均值含上偏 |
| D5 | 评分项自定义（dsv4flash 自定义"正文引用完整性"项） | 8.5 | Medium | 偏向 8-9，均值合理 |

### 5.3 方法论反馈

本次仲裁发现 3 个 skill 改进点，均已修复：

| 改进点 | 状态 | 修复方式 |
|--------|:---:|---------|
| D2/D5 引用问题归属边界 | ✅ 已修复 | skill 新增 5 类归属表 |
| D4 抽样代表性要求 | ✅ 已修复 | skill 新增全 Tree 覆盖 + 分层抽样要求 |
| 评分项不得自定义 | ✅ 已修复 | skill 新增 3 条评分项纪律 |

### 5.4 关键教训

1. **分歧根因多为方法论问题**（非能力偏差）→ 规则仲裁（P3）有效
2. **"AAI差≥10→三评审者"过度泛化** → 改为精准触发条件
3. **方法论校准可解决大部分分歧** → 仲裁作为残余分歧的兜底
4. **同模型自仲裁可行但非最优** → P4 限制为根因分析，不做独立打分

## 6. 与 skill 的关系

本协议是 `forest-quality-reviewer` skill 的补充资产：

- **SKILL.md** 定义 5 维度评分标准 → 仲裁时核对的标准来源
- **本协议** 定义分歧处理流程 → 评审者间分歧时的兜底机制
- **experiment_execution_sop.md** Step 4 引用本协议 → 对照实验中的仲裁执行

方法论校准（D2/D5 边界、D4 抽样、评分项纪律）是第一道防线，仲裁是第二道防线。校准后大部分分歧应消失，仲裁仅处理残余分歧。
