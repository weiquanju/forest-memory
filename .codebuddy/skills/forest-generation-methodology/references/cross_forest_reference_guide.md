# 跨森林引用建立指南（Cross-Forest Reference Guide）

## 概述

Step 4 定义了知识森林中两种引用关系的建立规范：**森林内部引用**（intra-forest）和**跨森林引用**（cross-forest）。引用关系将扁平的知识原子连接为**图网络**，是实现 MKE 五层架构中"图索引"和"多跳扩散检索"的基础。

## 两类引用对比

| 属性 | Intra-Forest（森林内部） | Cross-Forest（跨森林） |
|------|------------------------|----------------------|
| 格式 | `[tree_id] 文档标题 \| 原因` | `[forest_id] 文档标题 \| 原因` |
| 方向 | 同一 Forest 内不同 Tree 之间 | 不同 Forest 之间 |
| 目的 | 建立 Forest 内部的知识依赖图 | 建立 Forest 间的知识注入关系 |
| 频率 | 每个 Leaf 平均 2-5 条 | 仅在有明确的跨域消费时建立 |
| 维护者 | 自动检测 + 人工审核 | 主要由消费方 Forest 主动声明 |

## Intra-Forest 引用规范

### 引用格式

```yaml
# 在 Leaf 的 YAML Frontmatter 中：
refs:
  - "[tree_id] 被引用文档标题 | 引用原因简述"
```

### 引用方向规则

#### 规则 1：基础 → 进阶（最常见方向）

基础概念的 Leaf 引用进阶应用的 Leaf 时，进阶应用在 `refs` 中声明"依赖"基础：

```yaml
# Leaf: 键值记忆框架.md（属于"新兴理论"这棵树）
refs:
  - "[微观机制] Hebbian学习 | KV框架与Hebbian学习的互补关系"
  - "[宏观架构] 时间分层 | KV框架的时间分层启示"
```

**理由**：进阶概念通常建立在基础概念之上，引用方向应为"进阶 → 基础"（表示"我依赖你"）。

#### 规则 2：机制 → 应用

当某个机制的 Leaf 被某个应用的 Leaf 使用时：

```yaml
# Leaf: CAM寻址算法.md（属于"检索算法"这棵树）
refs:
  - "[微观机制] 模式分离 | CAM依赖于模式分离的稀疏表征"
```

#### 规则 3：理论 → 实证

当某个理论的 Leaf 有对应的实证支持时：

```yaml
# Leaf: BTSP行为证据.md
refs:
  - "[新兴理论] 键值记忆框架 | BTSP为KV框架提供行为层面的支持"
```

### 反模式（应避免）

| 反模式 | 为什么不好 | 正确做法 |
|--------|----------|---------|
| 双向互引（A→B 且 B→A） | 形成循环，破坏 DAG 性质 | 提取公共部分为独立 Leaf，或合并 A 和 B |
| 全量互联（每对 Leaf 都互相引用） | 引用失去信息价值 | 只在有直接依赖时才建立引用 |
| 跨层跳跃引用（Leaf 直接引用另一棵 Tree 的 Leaf，跳过中间层） | 违反层级封装 | 尽量在同一 Tree 内引用；跨 Tree 引用应通过 Tree 级 index 中转 |

## Cross-Forest 引用规范

### 引用格式

```yaml
# 在源 Forest 的 Leaf 中：
refs:
  - "[目标forest_id] 文档标题 | 知识注入说明"
```

### 建立条件

跨森林引用**不应滥用**——只在以下情况之一成立时建立：

1. **知识注入**：当前 Forest 的知识被目标 Forest 直接消费（MKE 最常见的场景）
2. **方法参照**：当前 Forest 的方法在目标 Forest 中被采用或修改
3. **对比基准**：当前 Forest 的内容在目标 Forest 中被用作对比对象

### MKE 项目实例：三支撑森林向 MKE 注入知识

| 7 | 稀疏编码原理 | 混合检索引擎 | 向量嵌入 + 稀疏化的组合 |

### 引用网络的图属性

理想情况下，整个项目的所有 Forest 通过 cross-forest refs 构成一个**有向无环图（DAG）**：

```
         ┌── bim ──┐
         │  (7条)  │
         └────┬────┘
              │ 注入
              ▼
┌── aic ──┐  ┌── mke（核心）──┐
│  (5条)  ├──┤   (消费方)      │
└─────────┘  └────▲─────┬─────┘
                   │     │
              ┌─────┘     │ 注入
              │  消费     │
┌── frs ───────┘          │
│ (6+4条)                │
└────────────────────────┘
```

**关键属性**：
- **mke 是汇点（sink）**——它是知识的主要消费者
- **bim/aic/frs 是源点（source）**——它们向 mke 注入知识
- **不存在环路**——mke 不会反向注入到 bim/aic/frs（除非有新的研究发现需要更新）
