# 森林主题设计原则（Forest Design Principles）

## 概述

Step 1 将原始资料映射为 `Forest → Tree → Branch` 的三级层级结构。这是从"扁平文档集合"到"结构化知识森林"的关键转换——设计的质量直接影响后续抽取、检索和维护效率。

## 核心原则

### 原则 1：树 = 子领域（Tree = Sub-domain）

每棵 Tree 对应一个**相对独立的子领域**或研究方向。判断标准：

- 该组内的知识原子在学术上有共同的"父概念"
- 不同 Tree 之间的交叉引用应尽量少（< 20% 的 Leaf 有跨 Tree refs）
- 如果移除一棵 Tree，剩余的 Tree 仍能构成一个自洽的知识体系

### 原则 2：枝干 = 话题类别（Branch = Topic Category）

每个 Branch 是 Tree 内的一组**功能相关**的话题。常见分类维度：

| 维度 | 适用场景 | 示例 Branch 名称 |
|------|---------|-----------------|
| **按抽象层次** | 理论性强的领域 | 基础理论 / 中层机制 / 应用实践 |
| **按功能模块** | 工程/系统领域 | 输入模块 / 处理模块 / 输出模块 |
| **按时间线** | 有演进历史的领域 | 早期工作 / 当前主流 / 前沿方向 |
| **按争议点** | 有分歧的领域 | 支持方观点 / 反对方观点 / 综合评价 |
| **按组件** | 复杂系统 | 架构设计 / 算法实现 / 评估方法 |

### 原则 3：叶子 = 知识原子（Leaf = Knowledge Atom）

每个 Leaf 是**单一职责**的最小知识单元。判断标准（来自 `knowledge-atom-extractor` 的 extraction_schema）：

- 一个 Leaf 只阐述一个核心概念/方法/发现
- 如果一个 Leaf 需要"第一部分...第二部分..."来组织，应该拆分
- Leaf 之间通过 `refs` 建立依赖关系，而非在正文中重复描述

### 原则 4：粒度控制（Granularity Control）

| 层级 | 推荐数量 | 过少的风险 | 过多的风险 |
|------|---------|-----------|-----------|
| Forest 内 Tree 数 | 3-12 | 太粗：单棵 Tree 承载过多异质内容 | 太碎：Tree 间边界模糊 |
| 单棵 Tree 下 Branch 数 | 3-8 | 缺少内部分类 | 分类过于琐碎 |
| 单个 Branch 下 Leaf 数 | 2-10 | 信息密度过高 | 原子粒度过细，维护成本高 |
| 单个 Leaf 字数 | 200-2000 | 不够独立成原子 | 违反单一职责，应拆分 |

## 设计流程

### 流程图

```
┌─────────────────────────────────────────────┐
│  Phase 1: 通读与提取                          │
│                                             │
│  通读所有输入资料                             │
│       ↓                                     │
│  提取所有核心概念/论点/方法/实验              │
│  （产出：无序列表 N 个知识点）                 │
└────────────────────┬────────────────────────┘
                     ↓
┌─────────────────────────────────────────────┐
│  Phase 2: 概念聚类                           │
│                                             │
│  对 N 个知识点进行语义聚类                    │
│  ↓                                          │
│  产出 K 个候选 Tree（K 建议 3-12）           │
│  每个候选 Tree 包含 M_k 个知识点             │
└────────────────────┬────────────────────────┘
                     ↓
┌─────────────────────────────────────────────┐
│  Phase 3: 组内细分                           │
│                                             │
│  对每个候选 Tree 内的知识点                  │
│  按"机制/应用/评估/局限"等维度细分           │
│  ↓                                          │
│  产出每个 Tree 下的 Branch 列表               │
└────────────────────┬────────────────────────┘
                     ↓
┌─────────────────────────────────────────────┐
│  Phase 4: 边界审查                           │
│                                             │
│  审查问题：                                  │
│  □ Tree 之间是否有重叠？（如有，合并或重划）   │
│  □ Branch 之间的边界是否清晰？                │
│  □ 是否有孤立的知识点无法归入任何 Tree？      │
│  □ Tree/Branch 的命名是否准确反映内容？      │
└────────────────────┬────────────────────────┘
                     ↓
┌─────────────────────────────────────────────┐
│  Phase 5: 命名规范化                         │
│                                             │
│  Tree 命名：<领域/子领域名称>                │
│    例："宏观架构"、"微观机制"、"新兴理论"      │
│                                             │
│  Branch 命名：<功能/话题描述>                │
│    例："时间分层"、"突触可塑性"、"检索算法"   │
│                                             │
│  Leaf 命名：<具体概念/方法名称>              │
│    例："短期记忆"、"Hebbian学习"、"CAM算法"  │
└─────────────────────────────────────────────┘
```

## MKE 项目实例：bim 森林的设计过程复盘

bim 森林从一篇综述论文的人脑记忆相关章节出发，经过以下步骤形成 6 棵树 22 个叶子：

| 步骤 | 决策 | 结果 |
|------|------|------|
| Phase 1 | 从综述中提取记忆相关的核心概念 | ~40 个知识点 |
| Phase 2 | 按抽象层次聚类为 6 组 | 6 个候选 Tree |
| Phase 3 | 每组内部按"架构/机制/算法/理论/未解/审计"细分 | 6×(2-5) 个 Branch |
| Phase 4 | 边界审查 | 发现"编码策略"与"检索算法"有重叠→调整边界 |
| Phase 5 | 命名 | 使用中文学术术语命名 |

**最终结构回顾**：

```
bim（类脑记忆机制）
├── 宏观架构（3 leaves）：时间分层/系统分工/内容分类
├── 微观机制（5 leaves）：突触可塑性/STDP/BTSP/稀疏编码/再巩固
├── 检索算法（3 leaves）：互补算法/CAM寻址/跨模态
├── 新兴理论（5 leaves）：KV框架/CLS/预测模型/RL驱动/共享记忆
├── 未解之谜（3 leaves）：SWR睡眠/杏仁核情感/全局工作空间
└── 文献审计（2 leaves）：引用审计/文献清单
```

## 常见设计陷阱及规避

| 陷阱 | 表现 | 规避方法 |
|------|------|---------|
| **扁平化** | 只有 1-2 棵大 Tree，每棵下几十个 Leaf | 强制 Tree 数 ≥ 3；如果某领域确实很大，考虑拆分为多个 Forest |
| **碎片化** | > 15 棵 Tree，每棵只有 1-2 个 Leaf | 合并语义相近的 Tree；使用 Branch 做更细的分类 |
| **循环依赖** | Tree A 引用 B，B 引用 A | 提取公共部分为独立 Tree 或合并 A 和 B |
| **命名歧义** | "记忆"同时出现在多个 Tree 名中 | 使用限定词："长期记忆" vs "工作记忆" vs "情景记忆" |
| **不平衡** | 某 Tree 有 20 个 Leaf，其他只有 2-3 个 | 重新审查过大的 Tree 是否可以拆分；或确认该领域确实更重要 |
