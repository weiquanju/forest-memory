# 迭代修正追踪策略（Iteration Correction Tracking）

## 概述

Step 7 将 Step 3（交叉声明检测）和 Step 5（引用审计）中发现的问题**结构化记录**，并将修正结果转化为 **Few-shot 样本**注入到后续的 LLM 抽取过程中。这是实现"越用越好"的闭环的关键。

## 修正日志格式

每次修正记录在一个统一的日志文件中：

```markdown
---
title: 迭代修正日志
forest: <forest_id>
version: 1.0.0
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

### Few-shot 反馈

> 此处描述如何将该修正转化为 knowledge-atom-extractor 的Few-shot示例

**转化方式**：
1. 描述原输入（导致错误的文档片段）
2. 描述期望输出（正确的结果）
3. 标注错误原因（为什么 LLM 会犯这个错误）
4. 给出避免策略（Prompt 中应强调什么）

**Few-shot 示例**：

```
## 输入（错误触发案例）
原文："...根据 van de Ven et al. (2024) 的研究..."
期望输出：
  refs:
    - "Parisiet al.(2019) ComplementaryLearningSystems | 替代原van deVen书籍章节"

错误原因：LLM 将书籍章节误认为期刊论文，且未注意到年份偏差
避免策略：在 System Prompt 中强调"优先引用期刊论文版本的综述"
```

## 迭代轮次的规划

### R1：首轮修正（前 10 个文档处理后）

**时间窗口**：完成首批文档抽取后立即执行

**关注点**：

| 检查项 | 方法 | 目标 |
|--------|------|------|
| 层级归属准确性 | 人工审核前 10 个 Leaf 的 `tree`/`branch` 字段 | 确保 LLM 理解了 Tree/Branch 的划分逻辑 |
| 拆分合理性 | 检查是否有 Leaf 内容过长（>3000 字）或过短（<100 字）| 校准"单一职责"的理解尺度 |
| YAML Frontmatter 完整性 | 检查关键字段是否缺失 | 确保输出格式符合 schema |

**产出**：R1 修正日志 + 至少 2-3 个 Few-shot 样本

### R2：批量修正（全部文档抽取完成后）

**时间窗口**：Step 2-3 批量处理完成后

**关注点**：

| 检查项 | 方法 | 目标 |
|--------|------|------|
| 交叉声明漏检率 | 人工抽查高相似度对（0.75-0.85 区间） | 识别漏报的重复声明 |
| 引用准确性 | 运行 Step 5 审计协议 | 修复引用元数据和语境问题 |
| 命名一致性 | 检查所有 Tree/Branch/Leaf 名称 | 确保命名规范一致 |

**产出**：R2 修正日志 + 引用审计报告 + 更多 Few-shot 样本

### R3：深化修正（评审后）

**时间窗口**：`forest-quality-reviewer` 评审完成后

**关注点**：基于评审报告中得分最低的维度做针对性改进

| 评审维度低分项 | 对应修正动作 |
|---------------|------------|
| 批判性分析（D4）低 | 在 Prompt 中增加"请讨论局限性""请与替代方法对比"指令 |
| 学术规范（D5）低 | 在 Prompt 中增加"请遵循学术写作规范"约束 |
| 引用准确性（D2）低 | 增加 Few-shot 中正确引用格式的样本权重 |

## Few-shot 反馈循环

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Step 2/3    │     │  Step 7     │     │  下一轮      │
│  LLM 抽取    │ ──→ │  修正记录    │ ──→ │  抽取（迭代） │
│             │     │  Few-shot    │     │  （含新样本） │
└─────────────┘     └──────┬──────┘     └─────────────┘
                           │
                           ▼
                  ┌─────────────────┐
                  │  knowledge-     │
                  │  atom-extractor │
                  │  的 few_shot     │
                  │  参数更新        │
                  └─────────────────┘
```

**收敛预期**：

| 迭代轮次 | 预期人工修正率 | 预期综合评分提升 |
|---------|:---:|:---:|
| R0（无迭代） | ~14%（基于 44 分模型基准） | 6.5/10 |
| R1（首轮 Few-shot） | ~10% | ~7.0/10 |
| R2（批量 Few-shot） | ~7% | ~7.5/10 |
| R3（评审驱动优化） | ~5% | ~8.0/10 |

**注意**：以上数值为基于 DeepSeek V4 Pro（44 分）的推断。更高能力的模型起始点更高，收敛所需的迭代轮次更少。
